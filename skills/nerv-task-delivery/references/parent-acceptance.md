# 多票父任务总体验收

## 触发与负责人

只有同一获批父 spec 拆成多张子 Issue 时使用。全部已批准子票的 PR 合并后执行一次；若调用只处理其中一部分，父任务状态保持未验收，等余下子票合并。

编排者在最后一张子 PR 合并后派一个父任务验收席位。该席位独立于编排者、所有子票实施席位及 PR 审核代理，不改代码，也不替代逐 PR 审核。单票 S/M 任务没有此阶段。

## 验收步骤

1. 读取唯一获批的父 spec、完整子票清单、每票验收标准、真实 blocker 边、共享契约和已声明的测试 seams。把父 spec 每条整体验收标准映射到至少一项组合行为或跨票路径。
2. 固定所有子 PR 合并后的 `main` SHA。逐项验证父 spec 的用户行为和跨票集成；单票分别 green 只证明各自子票，不构成父级结果。
3. 复用证据前确认它覆盖组合 SHA、父级标准和相同的相关环境。相同 SHA 但运行时、服务、配置、工具链或 fixture 发生影响结果的变化时，重新验证受影响项。记录父 Issue、组合 SHA、逐项结果、实际命令或 CI check、输出与相关环境摘要。
4. 若恢复时已有父级验收记录，先比较它绑定的 SHA、标准和相关路径变化。`main` 仅因无关提交前进时保留原证据，只重验受后续改动影响的标准。

整体验收仅在子票组交付后执行，不在每张子 PR 或每个修复轮次重复全 spec 审查或整批门禁。修复后只对失败或受影响的父级标准，在新的组合 SHA 上补验；只有改动影响其它标准时才扩展检查。

## 结果

- 所有父级标准均有通过证据时，向父 Issue 用中文评论记录验收结论和组合 SHA，并报告父任务完成；保留获批 spec 区块原样，不关闭父 Issue。子票 PR 全绿本身不能标记父任务完成。
- 任一标准失败、缺证据或环境不可用时，父任务保持未验收。报告未满足标准、SHA、环境和实际输出。范围内且已有批准子票覆盖的问题，交回对应子票的原实施席位；没有覆盖的，先按 `/to-tickets` 完成用户审批再开聚焦子票。整组其余证据继续保留，不为一次局部修复重跑无关门禁。
