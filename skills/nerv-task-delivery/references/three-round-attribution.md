# 每三轮归因

## 触发

一轮 = 审核代理发 PR 评论 → 编排者通知实施席位 → 原实施席位修复、重跑受影响门禁并 push、逐条回 PR → 原审核代理在新 head 上复审。

每完成三轮，在下一次修复前暂停逐条打补丁，做一次根因归因。归因是换挡，默认结果是按根因继续当前任务；只有方案明确超出原范围，或票本身需要拆分时才等待用户决定。

## 独立归因

- 原实施席位单独说明这三轮阻断的共同成因，以及先前修复为何没有触及它。
- 审核代理收齐所有实际派出的轴；每轴各自解释三轮未收敛的原因，不合并结论。说明是判据不清、证据要求不可执行，还是实现仍未解决问题。
- 编排者把两侧原始归因交给一个新代理。它必须既未实施也未审核本 PR，并判断问题属于实施侧、审核侧还是任务票本身；同时判断该票是否仍成立。

| 裁定 | 处理 |
|---|---|
| 实施侧 | 原实施席位提出根因级方案，交原审核代理裁断；方案在范围内时整体修复并继续原迭代 |
| 审核侧 | 原审核代理让对应轴重审并给出根因级判据，然后回原迭代 |
| 票本身 | 重新调用 `scope-gate`；按原范围拆出 ≤ M 子票或关闭当前 PR。子票须先经用户批准，再由 `/to-tickets` 发布；原实施与审核席位解散，子票各自新建席位 |

判断票本身的信号包括：三轮阻断没有重复、每轮长出新改动面；阻断散在互不相关的模块或业务域；修复 A 必然要改 B；验收条件到第三轮仍被两侧作不同理解。信号用于判断归属，不替代独立归因。

任何新方案仍须在原任务范围内收敛。原审核代理对方案作出三种裁断：

| 裁断 | 处理 |
|---|---|
| 原范围内 | 按方案整体修复，回到迭代；该方案之后重新计轮 |
| 明确超出原范围 | 暂停并上报根因、已试修法和剩余阻断，等用户决定 |
| 范围外的小型阻塞 | 原审核代理先确认方案，再按已批准流程开独立子票；由新实施与审核席位处理 |

子票不得由原实施席位顺手完成。归因次数不设上限：每次能指出新的成因且阻断在减少，就继续。连续两次归因得到同一成因，说明归因本身失效，按“票本身”处理并重新过 `scope-gate`。
