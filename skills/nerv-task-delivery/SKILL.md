# 在独立会话里把任务做到合并

**本技能是引导不是勾选表。** 它约束的是**谁做什么**与**什么时候停**，不规定实施手法。

**仅由用户手动调用。** 不要在别的任务中途顺手启动它。

本会话是**编排者**：传递信息、派单、汇报状态、在出严重问题时叫停。

**编排者不实施、不审核、不跑门禁、不 push、不建 PR、不合并**——这些全归席位。编排者只核对席位交回来的是实际输出还是声称。

留给执行者的判断：任务定级与拆分、模型档位、根因方案的取舍、何时叫停。

## 角色与隔离

| 角色 | 存续 | 约束 |
|---|---|---|
| 编排者 | 全程 | 只调度与汇报 |
| 实施席位 | 一 PR 一个，做到合并 | 全程同一个，含每一轮修复 |
| 审核席位 | 一 PR 一套，做到收敛 | 与实施席位不共享，复审回原席位 |

**不混合**：一个代理不得既实施又审核；一个代理不得同时实施两个 PR；审核席位不得动代码。

## 模型档位

默认与宿主会话**同模型同思考程度**——派单时不显式指定即继承。

简单任务只给**实施席位**降档，**审核席位不降档**：Claude 中用 sonnet，Codex 中用 luna max。

判据：单端点 / 单 handler 级修改、小 bug、机械收敛 → 可降档；架构、迁移设计、跨服务契约、前端大改 → 不降档。

## 1. 开工：一任务一树一分支

**REQUIRED SUB-SKILL：** `scope-gate` 先定级。L 级不进本技能——退回拆票。

- 一任务一棵持久工作树、一条分支，分支从最新 `origin/main` 起
- rebase 前重新 fetch 并验 ancestry
- 不用裸 `git stash` / `git stash pop`

## 2. 派实施席位

派单内容里写死：

- 任务号、验收条件**原文**、工作树**绝对路径**
- 席位自己跑受影响门禁、自己 push、自己建 PR；PR body 中文，带 `Fixes #<票号>`
- 跑门禁前先 `git add`——从 `git ls-files` 枚举的契约在 add 之前看不见新文件
- 席位不再派子代理
- 完成判据 = 门禁跑绿且回复里带**实际输出**，不是「应该会绿」；同时给出 PR 号与 head SHA

记住这个席位。后续每一轮修复都回到它，不新开。

## 3. 审核

**REQUIRED SUB-SKILL：** `nerv-pr-review`。**每个 PR 只调一次**，用它把这个 PR 的审核席位建起来并记住。

审核结论**原样**转给实施席位——不加工、不预先筛掉、不替席位判「这条不算」。

## 4. 迭代

一轮 = 回原实施席位修 → 席位重跑门禁并 push → 回**原审核席位**复审新 head。

**复审不重新调 `nerv-pr-review`**，交回第 3 步建起来的那套席位；它们带着上一轮的判断，能看出问题是修掉了还是搬家了。

各轴均无阻断即收敛，进第 6 节。

## 5. 三轮熔断

**第三轮结束仍有阻断：停止派修复。** 逐条打补丁到此为止，改成两侧各自归因。

**实施席位归因**：这些阻断的共同成因是什么，为什么前三轮的修法没触到它。

**四个审核席位各自归因**：本轴这条阻断为什么三轮没收敛——判据本身没说清、证据要求没给到可执行、还是问题确实在实现里没被解决。每轴各出各的，不合并。

两份归因**一起**交给一个**新的独立代理**——它既没实施过也没审过本 PR——只裁一件事：问题真正出在哪一方。

| 裁定 | 走法 |
|---|---|
| 在实施方 | 实施席位出解决方案，交**原审核席位**裁断后推进 |
| 在审核方 | **原审核席位**重新审核该轴，给出根因层面的修复判据，再回到第 4 节 |

方案必须在**原任务范围内收敛**——熔断是止损，不是重开设计。方案里出现新抽象、新分层、顺手重构，先按过度设计驳回。

原审核席位对实施方案的裁断三选一：

| 裁断 | 走法 |
|---|---|
| 在原任务范围内 | 按方案整体重做一轮；这一轮仍有阻断就上报用户，不再重置轮次 |
| 明确超出原任务范围 | 停下上报用户，附根因、已试修法、剩余阻断，等拍板 |
| 超出范围但属小阻塞 | 方案经审核通过后开**子票**，子票另起一树、另派独立实施与审核席位，同受本节约束 |

子票不得由原实施席位顺手做掉。

## 6. 合并与收尾

由实施席位做，编排者核对并汇报：

- CI 全绿 + 审核线程 resolve 之后才合
- 分支保护要求 up-to-date 时先 update-branch，并**盯到 MERGED**——auto-merge 不会更新分支，会一直干等
- `--admin` 绕保护先问用户
- 合并后中文回写票，指到 merge SHA；正文里的中文「关闭 #N」不触发自动关闭
- 自己开的 PR 只发 `COMMENT`

## 状态汇报与叫停

每个 PR 一行：任务号 / 分支 / PR / 当前轮次 / 阻断数 / 下一步。

只报实际执行证据，明确未运行项；区分本地测试、CI、真实运行、PR 合并、tracker 完成。

出这些情况立刻暂停并上报用户，不要让席位继续跑：席位改动溢出任务范围、门禁被绕过或删断言换绿、审核席位与实施席位的事实陈述互相矛盾、同一阻断换个说法反复出现。

## 与其它技能的边界

本技能拥有**编排**：任务 → 树 → PR → 审核 → 迭代 → 熔断 → 合并的调度与停止条件。

- 审核判据与分轴派席位归 `nerv-pr-review`
- 任务定级与拆分归 `scope-gate`
- 前端门禁命令归 `frontend-gate`
- `superpowers:subagent-driven-development` 管在**当前会话**执行既有计划；本技能管的是独立会话把票做到合并
