# 在独立会话里把任务做到合并

**本技能是引导不是勾选表。** 它约束的是**谁做什么**与**什么时候停**，不规定实施手法。

**仅由用户手动调用。** 不要在别的任务中途顺手启动它。

本会话是**编排者**：传递信息、派单、汇报状态、在出严重问题时叫停。

**编排者不实施、不审核、不跑门禁、不 push、不建 PR、不合并**——这些全归席位。编排者只核对席位交回来的是实际输出还是声称。

留给执行者的判断：任务定级与拆分、模型档位、根因方案的取舍、何时叫停。

## 角色与隔离

| 角色 | 存续 | 约束 |
|---|---|---|
| 编排者 | 全程 | 只调度与汇报，**不转述两侧内容** |
| 实施席位 | 一 PR 一个，做到合并 | 全程同一个，含每一轮修复 |
| 审核代理 | 一 PR 一个，做到收敛 | 调 `nerv-pr-review`、派四轴、汇总结论、把结论发成 PR 评论 |
| 四轴席位 | 由审核代理派 | 每轴一棵独立工作树，复审回原席位 |

**不混合**：一个代理不得既实施又审核；一个代理不得同时实施两个 PR；审核侧不得动代码。

## 模型档位

默认与宿主会话**同模型同思考程度**——派单时不显式指定即继承。

简单任务只给**实施席位**降档，**审核侧不降档**：Claude 中用 sonnet，Codex 中用 luna max。

判据：单端点 / 单 handler 级修改、小 bug、机械收敛 → 可降档；架构、迁移设计、跨服务契约、前端大改 → 不降档。

## 实施准则

**整段随派单交给实施席位与审核侧，不自行增删。** 它只管**做多少**，且只补 `nerv-pr-review` 各轴没管的那部分——抽象是否挣得到钱、有没有绕开 canonical helper、改动是否超出 spec，那些归审核的质量轴与规格轴，这里不复述。

### 不做

- **不为不可达状态兜底。** 兜底只写在真实可达的失败路径上。给类型系统已排除的分支、给不会为空的值、给不会抛的调用加 fallback、空分支、try-catch，是把噪声当健壮。
- **不给形状写测试。** 测试证明的是业务不变量——同一份输入下行为对不对。给命名、目录结构、文档格式、模板字段写守护脚本，除非那份形状本身就是本次任务的交付物。
- **不顺手修边界问题。** 路过发现的缺陷登记出去，不在本 PR 修。

### 做

- 优先选**行业普遍做法**。偏离要有本仓库或本任务的具体理由，不是偏好。
- 不确定该不该加时**不加**。少做可以补，多做要经过一轮审核才删得掉。
- 先让票面要的那件事成立，再谈周边。

### 野心用在删，不用在加

质量轴要求席位野心大一点、去找能让整类复杂度消失的重构——那是**删**的野心。本节的「少做」约束的是**加**：新分支、新兜底、新测试、新配置项。两者不冲突，同时成立。

### 审核侧同受此约束

- 审核不得把上面「不做」的三类要求回本 PR。
- 说「更健壮」「更完备」「补个测试」之前，先给出**会失败的具体输入或状态**。给不出就既不是阻断项也不是建议。
- 指出的问题超出票面范围时写成登记项，不写成本 PR 的阻断。

## 1. 开工：定级与排波

**REQUIRED SUB-SKILL：** `scope-gate` 先定级。

M 级及以下直接进第 2 节。

L 级不直接实施，但**正是本技能要编排的形状**——先拆成子票，再按子票之间的依赖关系排波次：

- 拆票方案与依赖关系**先报用户确认**，再建票开工
- 无依赖的子票**同一波并行**，各自一树一 PR 一套席位
- 有依赖的**串行**。判据：后一票要改前一票产出的文件或公开契约。前一票合并后，后一票再从新 `main` 起
- 一波之内某票熔断或被打回，不拖住同波其它票；下一波只等它依赖的那几票合并

每张票——子票同样——都是：

- 一棵持久工作树、一条分支，分支从最新 `origin/main` 起
- rebase 前重新 fetch 并验 ancestry
- 不用裸 `git stash` / `git stash pop`
- **不合并实施**：一票一 PR、一个实施席位、一个审核代理

## 2. 派实施席位

**派单只给指针，不给内容。** 票面在 issue / Linear 里，席位自己去读——编排者不复述、不预先解读、不替席位划范围。转述既丢信息又带偏。

只给三样：

- **票号**
- 工作树**绝对路径**
- 《实施准则》整段（它不在票里，席位也读不到本技能）

外加这几条规矩：

- 席位自己跑受影响门禁、自己 push、自己建 PR；PR body 中文，带 `Fixes #<票号>`
- 跑门禁前先 `git add`——从 `git ls-files` 枚举的契约在 add 之前看不见新文件
- 席位不再派子代理
- 完成判据 = 门禁跑绿且回复里带**实际输出**，不是「应该会绿」；同时给出 PR 号、head SHA，以及每条门禁结论**对应的那个 SHA**

记住这个席位。后续每一轮修复都回到它，不新开。

## 3. 审核

编排者为每个 PR 派**一个审核代理**，只给票号、PR 号、工作树路径与《实施准则》整段。

**REQUIRED SUB-SKILL——由审核代理调用，不是编排者：** `nerv-pr-review`。它负责钉事实源、派四轴席位、汇总四轴结论。**每个 PR 只调一次**，四轴席位从此归它。

**两侧靠 PR 沟通。** 审核代理把结论发成 PR 评论，实施席位去 PR 上读；席位每条的处理结果也回在 PR 上。编排者只通知一句「去看 PR 评论」，**不带内容**——它不需要知道结论是什么，也就无从转述、无从预先筛掉、无从替谁判「这条不算」。

以下几条由审核代理执行：

- **每轴一棵独立工作树**，用 `git worktree add` 从同一个 `.git` 建，不用 `git archive` 出副本——共享对象库，checkout 不重新传输，席位在自己树里能跑 git 命令，diff 不必另投。
- 钉**一次** HEAD：本地 HEAD 等于远端 PR head。钉过之后四轴直接用，不各钉各的。
- **门禁不重跑。** 一条门禁的结论是**树内容的函数**，跟谁在哪棵树上跑无关：实施席位在这个 SHA 上跑绿并交出实际输出之后，结论对四轴成立，换一棵树再跑一遍得不到任何新信息。CI 在干净树上跑过的同一个 SHA 口径更强，直接引用它。判据：**跑一条门禁之前，先说出它这次会给出什么上次没有的信息。** 说不出就别跑。
- 四轴该动手跑的只有**门禁跑不出来的那部分**：把实现改错，看断言会不会红。这一类只能在自己树里跑、也必然要重建——它不是重跑门禁，是门禁没做过的事。
- 依赖与包用现成的全局缓存（pnpm store、NuGet 包缓存），不自建缓存机制、不在席位之间拷产物。

## 4. 迭代

一轮 = 审核代理发 PR 评论 → 编排者通知实施席位去看 → 席位修、重跑门禁并 push、在 PR 上逐条回处理结果 → 审核代理钉新 HEAD，四轴在自己树里更新后复审。

**编排者在这个回路里只按门铃。** 它收状态、催进度，不搬内容。

**复审不重新调 `nerv-pr-review`**，交回第 3 步建起来的那套席位；它们带着上一轮的判断，能看出问题是修掉了还是搬家了。HEAD 一变，上一轮门禁结论随之作废——用实施席位在新 HEAD 上交出的那份。

各轴均无阻断即收敛，进第 6 节。

## 5. 三轮熔断

**第三轮结束仍有阻断：停止派修复。** 逐条打补丁到此为止，改成两侧各自归因。

**实施席位归因**：这些阻断的共同成因是什么，为什么前三轮的修法没触到它。

**四轴各自归因**（由审核代理收齐）：本轴这条阻断为什么三轮没收敛——判据本身没说清、证据要求没给到可执行、还是问题确实在实现里没被解决。每轴各出各的，不合并。

两份归因**一起**交给一个**新的独立代理**（由编排者派，它既没实施过也没审过本 PR）——裁两件事：问题出在哪一方，以及**这张票本身还成不成立**。

| 裁定 | 走法 |
|---|---|
| 在实施方 | 实施席位出解决方案，交**原审核代理**裁断后推进 |
| 在审核方 | **原审核代理**让该轴重新审核，给出根因层面的修复判据，再回到第 4 节 |
| 在票本身 | 重新过 `scope-gate`，按第 1 节拆票排波；本 PR 缩到其中一张子票的范围，或直接关掉，其余另起票另派席位 |

判「在票本身」的信号——**三轮的阻断没有一条重复**（每轮都是新面，说明范围在滚而不是修不对）；阻断散在互不相干的模块或业务域；修 A 必然要动 B；验收条件到第三轮还在被两侧各读各的。

拆票方案与依赖关系照第 1 节办：**先报用户确认**再建票。原实施席位与原审核代理连同四轴就地解散，子票各配新席位。

方案同受《实施准则》约束，且必须在**原任务范围内收敛**——熔断是止损，不是重开设计。

原审核代理对实施方案的裁断三选一：

| 裁断 | 走法 |
|---|---|
| 在原任务范围内 | 按方案整体重做一轮；这一轮仍有阻断就上报用户，不再重置轮次 |
| 明确超出原任务范围 | 停下上报用户，附根因、已试修法、剩余阻断，等拍板 |
| 超出范围但属小阻塞 | 方案经审核通过后开**子票**，子票另起一树、另派独立实施席位与审核代理，同受本节约束 |

子票不得由原实施席位顺手做掉。

## 6. 合并与收尾

由实施席位做，编排者核对并汇报：

- CI 全绿 + 审核线程 resolve 之后才合
- 分支保护要求 up-to-date 时先 update-branch，并**盯到 MERGED**——auto-merge 不会更新分支，会一直干等
- `--admin` 绕保护先问用户
- 合并后中文回写票，指到 merge SHA；正文里的中文「关闭 #N」不触发自动关闭
- 自己开的 PR 只发 `COMMENT`

## 状态汇报与叫停

每个 PR 一行：任务号 / 分支 / PR / 当前轮次 / 阻断数 / 下一步。

L 级另给一行波次：当前第几波、本波未合并的票、下一波卡在哪几票。

只报实际执行证据，明确未运行项；区分本地测试、CI、真实运行、PR 合并、tracker 完成。

出这些情况立刻暂停并上报用户，不要让席位继续跑：席位改动溢出任务范围、门禁被绕过或删断言换绿、审核侧与实施席位的事实陈述互相矛盾、同一阻断换个说法反复出现。

## 与其它技能的边界

本技能拥有**编排**：任务 → 树 → PR → 审核 → 迭代 → 熔断 → 合并的调度与停止条件。

- 审核的分轴判据与派席位归 `nerv-pr-review`，由审核代理调用它；《实施准则》只补它各轴未覆盖的部分，不复述、不改写分轴判据
- 席位怎么拿到待审的树归本技能：本技能派出的席位用 `git worktree add`，**覆盖** `nerv-pr-review` 的 `git archive` 副本做法；单独调那份技能审外部 PR 时仍按它原来的走
- 任务定级与拆分归 `scope-gate`
- 前端门禁命令归 `frontend-gate`
- `superpowers:subagent-driven-development` 管在**当前会话**执行既有计划；本技能管的是独立会话把票做到合并
