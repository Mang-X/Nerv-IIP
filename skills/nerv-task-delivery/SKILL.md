# 从已批准的票到合并

**本技能是引导，不是勾选表。** 它规定谁负责、何时继续或暂停，不规定实施手法。

**仅由用户手动调用。** 不要在别的任务中途顺手启动。

权威依据（读取，不复述）：`AGENTS.md`、`docs/superpowers/AGENTS.md`、`docs/governance/docs/language.md`、`skills/nerv-pr-review/SKILL.md`。

## 席位边界

| 席位 | 负责 |
|---|---|
| 编排者 | 接入已批准票面，派单、催进度、核对实际输出和汇报；不实施、审核、跑门禁、push、建 PR 或合并 |
| 实施席位 | 每张实施票一席位，负责整张票直到 PR 合并，包括其全部修复轮次 |
| 审核代理 | 每个 PR 一席位，负责调用 `nerv-pr-review`、起审核轴、汇总结论并写 PR 评论 |
| 审核轴席位 | 审核代理按改动面创建，每轴一席位，隔离评审并复审到收敛 |
| 父任务验收席位 | 多票组全部子 PR 合并后独立验收一次；不属于任一子票的实施或审核席位 |

一个代理不兼任同一 PR 的实施与审核；实施席位不同时承接两个 PR。审核侧不改代码。后续修复回原实施席位，复审回原审核侧。

## 1. 接入票面与恢复

本技能消费 GitHub 中已发布的 spec、plan 和子票，不重做已经批准的访谈或拆票。

| 上游调用 | 已完成产物 | 本技能接续 |
|---|---|---|
| `/to-spec` | GitHub Issue 原正文内唯一 `superpowers-spec` 区块，含已批准状态、修订号和日期 | 读取获批边界；不复问已决定内容 |
| `/to-tickets` | 已批准并发布的 GitHub 子 Issue；每票写明端到端交付、可验收标准、真实 `Blocked by` 边，无依赖时明确 `None` | 按现有依赖图执行 ready frontier；不重拟粒度或依赖 |
| `/nerv-task-delivery` | 一个或多个 GitHub Issue 编号，或唯一解析到 GitHub Issue 的 Linear key | 每张实施票一树、一分支、一 PR |

对 L / XL 父任务，`/to-spec` 的获批结果先于 `/to-tickets` 的拆票；两者均由用户手动调用。本技能不代替用户运行上游技能。缺少所需产物时，告诉用户准确的下一步调用：先对父 Issue 调 `/to-spec`、批准 spec，再调 `/to-tickets`、批准并发布子票，然后用子 Issue 编号重入本技能。沿用已给上下文，只问缺失的决定。S / M 票面若已足以验收，不额外要求 spec 或拆票。上游技能不可用时，报告技能名和受阻步骤，不仿写流程或自行安装。

每次开工或恢复时，从 GitHub 回读每张 Issue 的完整正文、标签、评论、子票和 blocker 边。若 Issue 使用 Superpowers plan，还要读取 plan 索引评论、逐 Task 评论和永久链接。spec、索引、Task 链接或审批状态缺失、重复、矛盾时，在建树、派席位或改票前暂停并报告具体缺项；产物完整且获批时直接接续，不重复确认。

GitHub Issue 是范围、spec 和子票的权威源。Linear key 沿现有 GitHub → Linear 同步元数据或稳定 cross-link 解析为唯一 GitHub Issue，核对精确 Linear key 及 canonical GitHub URL / number；不按标题模糊匹配，也不把 key 的数字部分当 GitHub issue number。零个或多个匹配时暂停，请用户提供 GitHub Issue 编号或链接。票面和 PR 只在 GitHub 更新，沿用现有同步；不直接创建或维护 Linear 票，同步延迟不阻塞 GitHub 流程。

多个输入先按 GitHub `Parent`、获批 plan 索引和 spec 归组。同一父 spec 的全部获批子票构成一个交付组。输入只包含其中一部分时，只处理这些票当前 ready 的部分，父级验收保持未完成，直到父票列出的全部子票合并。不同父票保持独立；只有同一父 spec 的完整子票组共用父级总体验收。

中断后使用同一 Issue 编号重入：重新读取审批、plan 评论、子票依赖、现有分支与 PR 当前 head、评论线程和 CI 状态，从第一个未完成边界继续。以持久化结果为准，不依赖旧会话记忆，不重开已完成的 spec 或 breakdown。

派单前确认当前路径的必需技能可用：`scope-gate` 负责定级，`nerv-pr-review` 负责每个 PR 审核；前端改动才需要 `frontend-gate`。上游产物齐全时不用重跑 `/to-spec` 或 `/to-tickets`；缺失时才检查对应用户手动技能。缺少当前步骤的必需技能时，报告准确名称和受阻步骤并暂停该票；不伪造替代结论或安装技能。

**接入完成条件：** 每个输入唯一解析到 GitHub Issue；所需审批、spec 与 plan 链接有效；当前 Scope Gate 级别、获批票组和 ready frontier 清楚。未满足时只做上游交接，不派实施席位。

## 2. 定级与依赖波次

**REQUIRED SUB-SKILL：** 创建或领取 Issue 时，以及每次开工前调用 `scope-gate`；实施中命中升级触发器时重判。已有级别时核对当前范围和理由，不重复定级访谈。

| 级别 | 交付形状 |
|---|---|
| S / M | 一张 Issue、一 PR；Issue 给出清楚且可观察的验收标准 |
| L | 先获批拆解；每张子 Issue ≤ M，都是可单独演示或验证的端到端窄切片 |
| XL | 先有获批 spec / ADR 与拆票方案；独立评审完成前不开实施票 |
| ? | 只启动限时 Spike / Investigation；不交付生产代码，结论用于重新定级和补票 |

已批准的 `/to-tickets` 子 Issue 和 `Blocked by` 图就是执行计划，不再询问粒度或依赖。`scope-gate` 决定交付形状和每票范围上限；`Blocked by` 只决定执行先后，不能从票的排列或创建顺序推断。

每张子票都覆盖跨需要层次的**完整用户行为**。验收标准须能用明确输入、状态或输出判定。共享公开契约、schema 或消费者测试 seam 若由上游票定义，下游票通过真实 blocker 边等待上游合并；票面写清契约行为和消费者验证。仅确实独立的票可同波并行；前置票合并后，依赖票从最新 `origin/main` 起新树。本流程不引入 integration branch。

**排波完成条件：** 每票不超过获批范围，拆票与边均已批准，待开工票的依赖均已完成或属于当前 ready frontier。

## 3. 实施一票一 PR

每张票一棵持久 worktree、一条分支、一位实施席位和一张 PR。分支从当时最新 `origin/main` 起；rebase 前重新 fetch 并核实 ancestry；不用裸 `git stash` / `git stash pop`。不要把多票合成一支 PR。

派单只给指针，不复述或预先解释票面：票号、worktree 绝对路径、《实施准则》整段。席位自己读取 GitHub Issue 和获批 plan，运行受影响门禁、push 并开中文 PR，正文带 `Fixes #<GitHub issue>`。跑门禁前先 `git add`，确保新增文件进入 `git ls-files`。实施席位不再派子代理。

模型默认与宿主会话同模型、同思考程度。简单单端点、小 bug 或机械收敛可只给实施席位降档（Claude 用 sonnet，Codex 用 luna max）；审核侧不降档。架构、迁移、跨服务契约或大前端改动保持默认档。

### 实施准则

**派单时将本节整段交给实施席位和审核侧。** 它补充 `nerv-pr-review` 未覆盖的实施纪律，不重复审核分轴。

- 优先用行业普遍做法；偏离须有本仓库或本票的具体理由。
- 先让票面要求成立，再碰周边。犹豫是否新增分支、兜底、测试或配置时先不加；范围外缺陷另登记。
- 防御落在信任边界，同一不变量只把关一次。只为可达的失败路径处理错误，不为类型已排除的状态兜底；不吞异常，不加没人要求的重试、超时或开关。
- 测试证明业务不变量，不守护命名、目录、文档格式或模板形状，除非形状本身就是交付物。
- 抽象以消除已有复杂度为目标，不增加 spec 未要求的机制。
- 审核也遵守这些准则；要求补测试或兜底前先指出会失败的具体输入或状态。范围外问题作为登记项，不作本 PR 阻断。

实施席位每轮保持不变。完成时给出 PR 号、head SHA、每条门禁的精确 SHA、实际命令和输出；不能用声称替代证据。

**实施完成条件：** 实际输出证明受影响门禁通过，PR 已推送且 head SHA 明确。不得把未运行项报告为通过。

## 4. 审核

**REQUIRED SUB-SKILL：** 每个 PR 由审核代理调用一次 `nerv-pr-review`，由它钉事实源、确定标准 / 规格 / 证据 / 质量四轴和审核席位。规格轴始终执行；其余轴按改动面选取。省略轴时须在 PR 评论写明依据；改动面变化时重判。审核分轴判据归 `nerv-pr-review`，本技能不复写。

审核代理和实施席位完全分离。每个并行审核轴使用独立 `git worktree add` worktree，共享 `.git`，不使用 `git archive`；审核轴不并行时可复用一棵树。审核代理只钉一次 HEAD，确认本地 SHA 等于远端 PR head，再把同一 SHA 交给各轴。审核结论写 PR 评论；实施席位逐条在 PR 上回处理结果。编排者只通知查看评论，不搬运或筛选内容。

门禁证据绑定确切 SHA、命令及会影响结果的环境（工具链 / 依赖、运行时服务、配置、fixture）。这些都相同时可由其它审核轴引用，换工作树本身不构成重跑理由。同 SHA 但环境不同，不自动视为同一证据；说明差异影响后，只补有信息增益的检查。相同 SHA 和门禁配置的干净 CI 结果优先引用。每次开跑前说清会得到什么上次没有的信息；说不清就不重跑。审核轴可在自己的树里验证门禁测不出的断言，例如故意让实现错误后观察断言是否变红；这不是重跑门禁。

HEAD 改变后重新钉 SHA，之前一轮的门禁结果不再作为新 head 的证据，使用实施席位针对新 SHA 的输出。依赖和包复用现有全局缓存，不自建缓存或在席位间拷产物。

**审核完成条件：** 当前 head 的所需审核轴均无阻断，PR review threads 已 resolve；下一步才能合并。

## 5. 迭代与归因

一轮 = 审核代理发 PR 评论 → 编排者通知原实施席位 → 实施席位修复、重跑受影响门禁并 push、逐条回 PR → 原审核代理在新 head 上复审。复审沿用已有 `nerv-pr-review` 席位，不重新调技能；改动面长出新轴时补轴。编排者只传达状态，不转述发现。

所有必需轴无阻断时进入第 6 步。每修满三轮，在下一次逐条修补前改做根因归因；此分支的完整裁定见 `skills/nerv-task-delivery/references/three-round-attribution.md`。每三轮归因默认继续原范围的修复；只有超出原范围或票本身需拆分时才等待用户决定。

**收敛条件：** 无阻断则合并；满三轮按归因参考文件裁定后继续；方案超范围或票需要拆分时暂停并上报用户。

## 6. 合并子票

实施席位在所有必需 CI 全绿且审核线程 resolve 后合并。分支保护要求 up-to-date 时先 update-branch，并确认 PR 达到 `MERGED`；auto-merge 不会替分支更新。绕过保护的 `--admin` 必须先获用户授权。

合并后用中文回写子票，指向 merge SHA。评论中的中文「关闭 #N」不会自动关闭 Issue。作者在自己开的 PR 上只发 `COMMENT`。

**子票合并完成条件：** PR 显示 `MERGED`，记录 merge SHA；这只完成该子票，不代表父 spec 验收通过。

## 7. 父级总体验收

同一获批父 spec 拆成多票时，全部子 PR 合并后派一个独立的父任务验收席位，并按 `skills/nerv-task-delivery/references/parent-acceptance.md` 验证一次完整 spec 和跨票集成。单票 S / M 没有此阶段。子票各自 green 不能代表父功能完成；此验收不在每轮或每波重复。

**父任务完成条件：** 每项获批父级标准在组合 SHA 上均有实际通过证据。失败、无证据或环境不可用时保持未验收，报告具体标准、SHA、环境和输出；范围内的修复回对应子票席位，没有已批准子票覆盖时先通过 `/to-tickets` 审批再开票。

## 8. 汇报与暂停

每个 PR 一行：Issue / 分支 / PR / 当前轮次 / 阻断数 / 下一步。多票父任务另报：父 Issue / 当前波次 / 未合并子票 / 阻塞依赖 / 父级验收状态与组合 SHA。

只报实际执行证据并注明未运行项，区分本地测试、CI、真实运行、PR 合并和 tracker 完成。

**汇报完成条件：** 每张票和每个父任务均有明确状态、精确 SHA、实际证据、未运行项和下一步；没有证据的结果标为未验证或阻塞。

席位改动超出票面、绕过门禁或删断言换绿、审核与实施的事实陈述矛盾，或同一阻断换说法重复出现时，立即暂停并上报用户。
