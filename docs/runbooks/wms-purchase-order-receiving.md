# WMS 采购订单待收货自动建单

WMS 按部署 profile 消费 ERP 采购订单下达 V2 事件。来源键使用 ERP 在组织和环境内唯一的采购单号，与 ERP 取消入库来源使用同一编号。建单时保存原采购行号和预期数量，实际收货量为零。

## 配置

按部署范围同时核对两端配置。ERP 的 `PurchaseOrderReceiving:WmsScopes` 决定采购单收货归属，WMS 的 `PurchaseOrderReceiving:Routes` 决定是否能为该范围建单及使用哪个收货暂存位。两端每条启用记录的 `OrganizationId`、`EnvironmentId`、`SiteCode` 必须逐值相同，且各自唯一。检查实际部署配置的三元组集合一致后，再准备开启 ERP 归属。环境变量可用两端各自的数组索引，例如 `PurchaseOrderReceiving__WmsScopes__0__SiteCode` 与 `PurchaseOrderReceiving__Routes__0__SiteCode`。

确认站点的采购收货规则后，在 WMS 对应路由补齐以下字段。

- `StagingLocationCode` 使用该组织、环境和站点下经确认可用的收货暂存位。WMS 此处的入库聚合按站点和暂存位建单，仓库由实际库位归属决定。
- `QualityStatus` 按确认的规则设置为 `quality` 或 `unrestricted`。
- `OwnerType` 显式填写 `company`。存在寄售或其他货权、或按物料和供应商区分规则的站点保持未配置。

ERP 缺少范围时按 Direct 归属处理。ERP 已标记 WMS 归属且 WMS 缺少匹配路由时，事件进入 WMS 死信，失败码为 `missing-purchase-order-receiving-route`。

生产保持 `WmsScopes` 与 `Routes` 为空。先部署支持非限制库存受理与完成回执的 ERP，再部署 WMS。在隔离环境配置成对的三元组，验证采购下达后自动建单、ERP 权威受理、WMS 全行全量实收、库存过账及完成回执。再用范围外采购单确认仍走 Direct。生产开通同一范围时先配置 WMS 路由并核对生效，再配置 ERP 对应范围。配置不配对或验收失败时停止启用。回退时先停止 ERP 对新采购单采用 WMS 归属，保留 WMS 路由，直到已归属 WMS 的采购单、待消费事件和在途批次完成对账，再撤下路由。已提交的预期入库单和已受理批次保留原收货归属及质量状态。

## 已提交取消与实收边界

ERP 为明确归属 WMS 的采购订单在取消事务内写入 V1 事件。WMS 按组织、环境和采购单号，在同一事务写入取消 inbox、来源终态投影并关闭未受理的自动入库单。即使取消先于下达消费也能吸收匹配的迟到下达。旧的按来源取消接口保留已暂存、已确认或已受理的自动收货，人工入库单继续走各自的流程。

相同来源的取消重投须匹配 ERP 采购单 ID、站点和取消提交版本。下达 V2 按 ERP 采购单 ID 和站点匹配终态。来源事实冲突时，记录 `purchase-order-cancellation-conflict` 死信。Direct 和缺少收货归属字段的旧下达先按原规则跳过自动流程。

## 死信恢复

1. 通过 WMS 死信查询保留原事件和失败码。重放前在 ERP 核对同范围采购订单仍可收货，并核对原下达行与当前订单。已取消或已变更的订单需要先对账。
2. 缺少配置时，按上节补齐后重放原 WMS 死信。遇到 `purchase-order-inbound-conflict` 时，先核实已有收货单、实收及过账事实。已实收或过账的单据由业务人员对账。若确认是尚未收货且单号不同的重复人工预期，可通过受治理的取消操作取消人工单，再重放原事件。采购单号本身已被占用时，保留冲突交人工处理。
3. 查询持久入库单或来源终态，核对组织、环境、采购单号及其原始行。记录原死信 ID、重放结果和入库单号或 ERP 取消依据。

## ERP 实收批次与启用顺序

WMS 先保存批次 UUID、原确认请求的幂等键、汇率和逐行请求数量。ERP 以组织、环境和批次 UUID 定位受理结果。超时或返回并发冲突后，按原确认请求重试。WMS 优先查回已提交的结果，查无结果时发送同一批次和冻结数据。绑定 ERP 收货单号时才一并写入实际收货量和确认凭据。

ERP 取消与 ERP 收货受理竞争同一个采购订单版本。WMS 来源事务锁协调预期建单、暂存、绑定和取消投影。ERP 先取消时，终态投影关闭未受理入库单并保留原请求和零实际收货量。ERP 先受理时，响应丢失后的原请求可查回已提交结果。库存过账按批次查回 ERP 受理结果，逐一核对原采购行与收货单号，使用 ERP 冻结成本在收货暂存位过账。重试仅重发失败行的原移动请求，沿用范围、批次、原行号及成本。WMS 收到该批次所有原行的库存过账回执后才发送完成事件。ERP 核对同范围受理记录并写入消费凭据，沿用原 ERP 收货单。当前自动入库单只受理一次全行、全量确认。检验任务源于 ERP 收货事件。上线验收应覆盖响应丢失、取消与实收竞态，以及来料合格、让步放行和拒收。待检实收按现行规则计提 GR/IR，拒收后的退货和财务处置须关联原收货批次。

ERP 批次受理事件携带原 WMS 批次 UUID。Quality 以 ERP 收货单号和原采购行生成待检任务，提交结果时发布同一批次和原行号。WMS 按组织、环境、批次和 ERP 收货单号定位绑定，再核对原行、SKU、物料批号和实收量。遇到 `erp-receipt-acceptance-not-bound`，先恢复原批次绑定，再重放原死信。遇到 `erp-receipt-quality-result-conflict`，保留首个已记录判定并核对 ERP、WMS、Quality 三方事实。

有待检行的批次须等所有待检行完成判定，再刷新入库单并执行完成。合格行进入非限制库存（`unrestricted`），让步放行行进入限制库存（`restricted`），拒收行在原收货暂存位进入冻结库存（`blocked`）。全部原行的 Inventory 回执提交时，WMS 为每个拒收行生成一张退供申请及出库单。退供拣货和过账使用原暂存位及 Inventory 回执中的实际生产日期、效期，空日期也是库存键的一部分。完成入库请求的原始日期继续用于幂等校验。ERP 以原收货单号及采购行接收退供出库完成事实，沿用[采购退货会计规则](../architecture/business/erp-return-accounting.md)。保持生产收货归属配置关闭，直到跨服务收货、检验、库存回执和拒收处置通过上线验收。
