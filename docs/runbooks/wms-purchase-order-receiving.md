# WMS 采购订单待收货自动建单

WMS 按部署 profile 消费 ERP 采购订单下达 V2 事件。来源键使用 ERP 在组织和环境内唯一的采购单号，与 ERP 取消入库来源使用同一编号。建单时保存原采购行号和预期数量，实际收货量为零。

## 配置

在 WMS 的 `PurchaseOrderReceiving:Routes` 中按 `OrganizationId`、`EnvironmentId`、`SiteCode` 配置唯一条目。在确认该站点的采购收货统一采用同一规则后，填入以下字段。

- `StagingLocationCode` 使用该组织、环境和站点下经确认可用的收货暂存位。WMS 此处的入库聚合按站点和暂存位建单，仓库由实际库位归属决定。
- `QualityStatus` 按确认的规则设置为 `quality` 或 `unrestricted`。
- `OwnerType` 显式填写 `company`。存在寄售或其他货权、或按物料和供应商区分规则的站点保持未配置。

缺少匹配项时，事件进入 WMS 死信，失败码为 `missing-purchase-order-receiving-route`。删除配置项会停止该范围的新建单。已提交的预期入库单继续保留。

启用前需验证 ERP 取消先于 WMS 消费时的处理，以及实际收货与 ERP 过账路由。当前按来源取消只处理已经存在的入库单。取消发生在首次消费之前时，迟到的原下达事件仍可能创建预期。

## 死信恢复

1. 通过 WMS 死信查询保留原事件和失败码。重放前在 ERP 核对同范围采购订单仍可收货，并核对原下达行与当前订单。已取消或已变更的订单需要先对账。
2. 缺少配置时，按上节补齐后重放原 WMS 死信。遇到 `purchase-order-inbound-conflict` 时，先核实已有收货单、实收及过账事实。已实收或过账的单据由业务人员对账。若确认是尚未收货且单号不同的重复人工预期，可通过受治理的取消操作取消人工单，再重放原事件。采购单号本身已被占用时，保留冲突交人工处理。
3. 查询持久入库单，核对组织、环境、采购单号及其原始行。记录原死信 ID、重放结果和入库单号。

## ERP 实收批次与启用顺序

ERP 的内部实收接口以组织、环境和 WMS 生成并持久化的批次 UUID 定位一次收货。同一批次重试须提交原采购单、站点、汇率和实收行。请求超时或返回提交并发冲突后，可按批次查回已提交结果。查无结果时保留批次并以原请求重试。查回结果中的收货单号与行价、汇率可用于后续过账。

启用前先将 ERP 取消改为与采购单在同一事务内提交的事件，并让 WMS 保留取消凭据以处理迟到的采购下达。随后接入 WMS 持久批次及 ERP 结果绑定，按该绑定推进库存并避免旧完成投影重复记收货。接入 Quality 时须统一 ERP 收货与 WMS 完成事件的来料检验来源，并将检验结果关联回同一批次。上线验收应覆盖响应丢失、取消与实收竞态，以及来料合格、让步放行和拒收。待检实收按现行规则计提 GR/IR，拒收后的退货和财务处置须关联原收货批次。
