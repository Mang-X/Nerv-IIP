# 决策记录内容分层治理

本文规定什么内容属于 ADR/决策记录、什么内容必须回到 Architecture / Governance / Reference / Status / Report / Product，以及 ADR 生命周期的结构不变量。

`docs/AGENTS.md` 是人工文档触发入口；本页是决策记录分层与生命周期规则的当前权威来源。结构门禁由 `scripts/verify-adr-format.ps1` 强制，门禁与本页的成文规则必须保持同强度。

产品文档信息架构由 `docs/adr/0021-product-docs-information-architecture.md` 治理，不在本页重复。

## 唯一判据：这段内容什么时候会变

分层按**变更频率**，不按“听起来像不像决策”。

| 内容 | 什么时候会变 | 当前落点 |
| --- | --- | --- |
| 决策、理由、被否决的备选、复评触发条件 | 只有新决策取代时变化；旧判断不就地改写 | `docs/adr/` |
| 当前必须遵守的工程规则 | 规则本身变化时 | `docs/governance/` |
| 当前系统组件、边界、所有权和交互 | 实现/架构变化时 | `docs/architecture/` |
| Schema、码表、矩阵、术语、资料等人工查询索引 | producer 变化时 | `docs/reference/` |
| 实施进度、责任票、阻塞和验收状态 | 每次推进都可能变化 | GitHub / Linear；全仓摘要仅 `docs/status/current.md` |
| 调查、事故、审计、修复证据与时点结论 | 对应事件完成后冻结 | `docs/reports/` |
| 用户、角色、业务流程、IA/UX | 产品裁决变化时 | `docs/product/` |

判断一段内容是否应该留在 ADR，只问：**下一次实现推进会不会让这段话变成过期描述？** 会，就不是决策记录。

### 表达形式不决定归属

图、矩阵、状态机、时序和接口清单既可能是规范性裁决，也可能是当前实现描述。按语义判断：

- `必须`、`不得`、`只能`、失败不变量、复评触发条件等规范性内容可以留在 ADR；
- 带日期的增量、当前类/方法/路径如何实现、完成率、票映射、运行结果等描述性内容离开 ADR；
- 不因小节标题里出现“矩阵/状态机/时序/接口”就机械搬走，必须读其约束语义。

## ADR 的职责与骨架

`docs/adr/` 只收在任务结束后仍会约束实现的长期决策，例如服务边界、契约、存储/消息基线、部署拓扑和命名/隔离策略。

推荐骨架：

```markdown
# ADR NNNN：<标题>

- 状态：已接受 | 已否决 | 被取代 — <一句话说明>
- 日期：YYYY-MM-DD

## 背景
## 决策
## 理由
## 实施说明
## 已考虑的替代方案
## 后果
## 范围之外
```

- `## 背景`、`## 决策`、`## 已考虑的替代方案` 是当前门禁要求；`## 决策` 可拆为 `## 决策 N：…`。
- 领域专属技术小节可以存在，但不能把实现进度伪装成技术小节。
- `## 范围与非范围` 同时定义 in/out scope，是合法独立小节；它不是 `## 范围之外` 的同义别名。

### 同义异名禁用表

| 禁用 | 规范值 |
| --- | --- |
| 影响、结果 | 后果 |
| 范围外事项、范围外 | 范围之外 |
| 备选方案、替代方案、已考虑的方案 | 已考虑的替代方案 |

### 生命周期禁用标题表

决策记录写裁决，不写提案期或进度期段落。下表与 `scripts/verify-adr-format.ps1` 中的生命周期列表逐字对齐，并由 `scripts/tests/verify-adr-format-lifecycle.Tests.ps1` 双向验证。

| 禁用标题 | 匹配方式 |
| --- | --- |
| `实施` | 前缀 |
| `迁移计划` | 前缀 |
| `验收标准` | 前缀 |
| `验收条件` | 前缀 |
| `当前实现` | 前缀 |
| `下一步` | 前缀 |
| `待办` | 前缀 |
| `计划` | 前缀 |
| `路线图` | 前缀 |
| `进度` | 前缀 |
| `票映射` | 前缀 |
| `Proposal` | 全等 |
| `Plan` | 全等 |
| `Migration plan` | 全等 |
| `Acceptance criteria` | 全等 |
| `Next steps` | 全等 |
| `TODO` | 全等 |
| `Roadmap` | 全等 |
| `Implementation status` | 全等 |

中文项按序数前缀匹配，以覆盖 `实施状态` / `实施状态声明` 等同类变体；英文项按忽略大小写的全等匹配，避免误伤 `Complete 提交时序` 等合法领域标题。

**白名单：`## 实施说明`**。它只豁免 `实施` 前缀禁令，不豁免日期戳禁令。

任何 `##` 及以下标题只要包含 `YYYY-MM-DD` 日期就是违规。决策变化必须新开记录或按下述部分取代规则处理，不能把 ADR 写成按日期累积的 changelog。

生命周期门禁只检查标题，不下探正文；正文中的耐久票号、日期或引用可以是决策背景/修订依据，不能因为出现日期就一律误伤。

## 决策变化：新记录取代，不叠加状态段落

### 整篇取代

旧记录状态改为 `被取代 — 由 ADR NNNN 取代`；新记录在背景中说明取代对象和原因。旧记录原始判断保持不动。

### 部分取代

只有部分条款被推翻时，旧记录仍有有效部分，因此状态保持 `已接受`：

1. 旧记录头部增加 `- 修订依据：[ADR NNNN：<标题>](NNNN-slug.md)`；
2. 旧记录的 `## 实施说明` 追加编号项，精确说明从何时起哪些条款不再成立、由哪篇 ADR 替代以及仍有效的部分；
3. 原条款文本保持原样，不就地改写历史判断；
4. 新记录 `## 背景` 点名被推翻条款，`## 已考虑的替代方案` 至少登记“维持旧判断”这一被否决方案。

需要核对仓库既有写法时可参考 ADR 0012/0014 与 ADR 0014/0025 的修订关系；这些实例是示例，不构成项目状态。

## 门禁强制面

`scripts/verify-adr-format.ps1` 当前校验：

- 文件名 `NNNN-kebab-case.md`；
- 首行 `# ADR NNNN：<标题>` 且 H1 编号与文件名一致；
- ADR 编号唯一；
- `- 状态：` 使用允许值；
- `- 日期：YYYY-MM-DD`；
- `## 背景`、`## 决策`、`## 已考虑的替代方案`；
- 同义异名小节禁用；
- 本页生命周期禁用标题与 `## 实施说明` 白名单；
- `##` 及以下标题日期戳禁令。

`scripts/tests/verify-adr-format-lifecycle.Tests.ps1` 负责证明表格与脚本列表双向一致，并用正/负 mutation cases 验证鉴别力。**迁移本页路径时只允许重定向 consumer，不允许借机改变列表、白名单或 mutation contract。**

## 审核决策记录

人工审核至少检查：

1. 是否缺少真实替代方案或将落选理由凭空补写；
2. 是否混入实施状态、票映射、路线图或日期化增量；
3. 技术矩阵/状态机究竟是规范性不变量还是当前实现描述；
4. 是否把参考数据附录、可生成清单或时点扫描塞进 ADR；
5. 整篇/部分取代关系是否双向可追；
6. 搬迁或改名是否同步处理活跃入链。

历史审计发现、欠账批次和清理计数不在本页保存；它们通过 Reports、Issue/PR 与 Git 历史追溯。
