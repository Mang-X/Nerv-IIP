# 文档与协作语言治理

本文规定 Nerv-IIP 仓库**面向人的文本**默认使用简体中文，并明确哪些内容必须保留英文/原文。语言治理只约束表达，不改变代码行为、契约、机器输入或第三方协议。

## 默认语言

下列人工内容默认使用简体中文：

- README、Architecture、Governance、Runbook、Reference、Product、Report 等人工文档；
- GitHub Issue / PR 的标题、正文、评论、Review 与状态说明；
- Linear issue、comment、project update；
- 面向仓库协作者的 AGENTS/Skill 说明、验收结论和人工操作说明。

用户或上游规范明确要求其他语言时按任务要求执行，但不要为了统一外观翻译机器契约。

## 必须保留英文或原文的内容

以下内容保持其可执行、可搜索或标准化形式：

1. 代码、命令、路径、文件名、配置键、环境变量、JSON/YAML 字段、HTTP method/path；
2. 类、方法、类型、package、framework、product、protocol、标准名、错误码、permission code、operationId、event name 等标识符；
3. 第三方 API/CLI 的精确参数与输出片段；
4. 为跨语言检索必须保留的官方术语，如 OAuth/OIDC、OpenTelemetry、CAP、CleanDDD；
5. 必要的短外部引文。引文只保留验证所需原文，正文解释仍用中文。

不要翻译后再发明一个无法在代码/官方文档中搜索到的新术语。首次出现专业英文时可附中文解释，后续保持稳定叫法。

## GitHub / Linear 协作

1. 标题与正文默认中文；路径、SHA、check name、label、branch、代码标识符保持原样。
2. Review finding 先写可验证问题，再给证据路径/行；不要为了中文化改写代码标识符。
3. CI、测试和合并证据必须使用真实 check/job/run 名称，不翻译成另一套名称后声称已执行。
4. 自动生成的机器人文本、外部系统固定字段或连接器要求的英文结构保持其机器格式；人工解释用中文。

## 机器输入排除原则

不能因为文件扩展名是 `.md`、`.json` 或“看起来像文字”就批量翻译。先判断消费者。

| 类型 | 处理 |
| --- | --- |
| 编译/运行输入、配置、schema、manifest、lockfile、snapshot/golden、fixture、提示词协议、工具元数据 | 保持机器契约；只有对应 producer/consumer 同时变更时修改 |
| 生成物或代码生成输入 | 修改 producer，不手改生成结果；按生成链重建 |
| 人工说明但夹带代码/命令/路径/标识符 | 说明中文，机器片段保持原样 |
| 外部协议/标准/厂商固定字段 | 保留原文，必要时旁注中文 |

## 精确路径纪律

1. 修改文本前先确认文件是人工文档还是机器输入/生成物；目录名本身不决定分类。
2. 对机器输入做语言变更时必须能点名 producer、consumer 与兼容影响；无法说明时不要改。
3. `docs/reference/` 可能包含人工索引，也可能链接机器生产者；Reference 不意味着可以翻译 producer。
4. `docs/reports/` 和历史快照可以保留当时英文证据，不为“统一中文”改写冻结记录。
5. ADR 的历史判断不因语言治理就地重写；若只是新建/正在修改的人工 ADR，按当前规则使用中文说明并保留技术标识符。

## 不使用字符比例门禁

不得用“中文字符占比”“英文词数量”“检测到英文即失败”等自然语言 scanner 作为仓库语言门禁。它会误伤代码、路径、技术名词和引文，并诱导文档为过门禁而失真。

语言质量靠：

- 明确人工文本范围；
- Review 判断表达是否可读；
- 机器输入通过其真实 parser/build/test 验证；
- 必要时对特定结构做窄、可解释的契约检查，而不是扫描自然语言内容。

## 修改与审核分工

- 实施者只翻译/重写任务直接覆盖的人工文本，不扩大到冻结历史、机器文件或无关目录。
- 审核者重点检查：是否误改标识符/命令、是否破坏链接、是否把历史证据改成当前结论、是否翻译了机器字段。
- 因语言调整导致的代码/契约行为变化属于越界，必须拆回真实功能任务。

## 完成条件

一次语言治理相关变更至少满足：

1. 人工文本主体语言符合当前规则；
2. 代码、命令、路径、标识符和机器结构保持可执行/可搜索；
3. Markdown 链接和相对路径在迁移后仍正确；
4. 机器输入由其真实 consumer 验证，而不是靠语言扫描器；
5. 未把 GitHub/Linear 状态、历史审计或时点计数复制进长期文档。
