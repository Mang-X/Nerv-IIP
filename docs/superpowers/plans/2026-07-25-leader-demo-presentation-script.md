# 领导演示讲稿 v1（MAN-520 / #961）

> 演示 commit（固定）：`e6a3224`（后续 docs-only 合并不影响该锚定；演示环境按此 SHA 部署）。
> 时长目标：20–25 分钟。环境：`.\nerv.ps1 demo start` + `seed` + `health-check`（Redis 跨进程 + PostgreSQL，见 `infra/aspire/README.md`）。
> 纪律（#961）：不开开发者工具、不手改数据库、页面不出现裸 GUID/英文堆栈；每个等待步骤都有加载态与有界超时。

## 演示叙事主线

一句话故事：**同一张客户订单，从接单到收款全程可追、出了问题系统自己会说话。**

三个记忆点（贯穿讲解反复回扣）：
1. **一单到底**——任何页面都能沿业务编号追到上下游；
2. **异常闭环**——质量和设备的意外不靠人盯，系统驱动处置并自动恢复；
3. **可解释**——每个评分、每次排程、每条预警都能点开看依据。

## 第 0 段 · 开场（1 分钟）

- 页面：经营总览。
- 讲：今天用一张真实订单走完工厂全流程。所有数据经真实数据库与消息总线，不是录屏或假数。
- 动作：指出今天的主角订单号（`SO-DEMO-001`），说明"记住这个号，它会一路出现"。

## 第 1 段 · 销售与履约总览（2 分钟）

- 页面：ERP 销售订单列表 → 行内「履约追踪」。
- 动作：打开履约时间线，展示 13 节点全链视图；指出已确认节点（可下钻）与「尚未建立关联」节点的显式说明。
- 讲：这张时间线是演示的地图——接下来每做一步，回到这里就能看到节点点亮。**诚实说明**：部分节点的关联键还在按治理节奏补齐，系统宁可显示"尚未建立关联"也不猜。
- 记忆点回扣：一单到底。

## 第 2 段 · 需求与计划（2 分钟）

- 页面：需求计划（DemandSource / MRP）。
- 动作：展示销售订单确认后自动生成的需求源（`sourceReference = SO-DEMO-001`）；接受 MRP 建议生成计划工单。
- 讲：从"客户要什么"到"工厂造什么"零手工转录。

## 第 3 段 · APS 排程与动态重排（4 分钟，高光段一）

- 页面：排程工作台（`WorkingScheduleDraft`）。
- 动作：
  1. 批量生成排程方案，展示紧急度徽章与七种显示模式切换（业务优先级 / CR / Slack / 预计延迟…）；
  2. 打开某订单解释 Sheet：展示紧急度三维分解与阈值判定表——**可解释**；
  3. （可选）现场设置一条 P0 人工优先级（必填原因），展示审计历史立即出现新修订；
  4. **动态重排**：触发一次失效（或指出已失效方案），在工作台重新生成 → 新旧方案 KPI 对比（准交率/延期/移动工序数）→ 受治理发布新版。
- 讲：1000 张订单 36 秒排完（有基准证据）；变化来了不是推倒重来，是"看清影响、对比方案、审计发布"。
- 数字弹药：APS Lite 基准 100/500/1000 档三次输出哈希一致。

## 第 4 段 · MES 执行（2 分钟）

- 页面：MES 工单 / 派工。
- 动作：方案发布后工单进入执行；完成报工（展示报工单号）。
- 讲：计划到执行是同一份事实，报工立刻回流成本与质量。

## 第 5 段 · 质量闭环（4 分钟，高光段二）

- 页面：质检工作台 → NCR 详情 → 工单详情 hold 区块。
- 动作（完整闭环，全部现场真做）：
  1. 报工自动触发检验任务；录入**超差**测量值 → 判不合格；
  2. 系统生成 NCR（展示可读 NCR 号）、工单自动进入质量 hold（列表出现锁定图标）；
  3. **NCR 处置**：发起返工处置 → 中央审批链审批通过 → 处置生效（页面回读处置类型与审批链依据）；
  4. **复检合格 → hold 自动释放**：录入合格复检 → 等几秒 → hold 徽章自动消失，时间线完整记录"施加→自动释放"两条记录（origin=automatic）。
- 讲：不合格不是流程终点，是闭环起点——处置有审批、复检有记录、解锁不用人催。SPC 控制图与 NCR Pareto 顺带一览（下钻入口）。
- 记忆点回扣：异常闭环。

## 第 6 段 · 设备健康（4 分钟，高光段三）

- 页面：设备详情（健康评分卡 + 历史遥测折线）。
- 前置：设备模拟器 `degrading` 场景已按时间轴编排（讲到本段时振动正逼近阈值）。
- 动作：
  1. 展示健康评分与五条规则逐项依据（当前值/阈值/证据）——**可解释**；
  2. 现场看着振动趋势逼近阈值 → 报警触发 → **健康评分实时下降、等级翻转**；
  3. 报警确认 → 生成维修工单 → 设备不可用窗口出现（排程侧可见影响）；
  4. 维修恢复 → 状态回落，可靠性指标更新（故障计数、MTBF）。
- 口径纪律：**MTTR 显示"数据积累中"**——如实讲"完工维修的原因目录还在接入，指标随运行数据积累启用"（#1105 按 B 口径）。零数据设备显示"暂无数据·历史数据积累中"，绝不凭空打 100 分。
- 讲：设备不舒服，系统比老师傅先知道，而且说得出为什么。

## 第 7 段 · 入库、发货与财务（3 分钟）

- 页面：完工入库 → 成品批次/库存 → 发货单 → WMS 出库 → 应收/凭证。
- 动作：完工入库（含单位成本自动资本化——指出成本率来自工作中心公开配置）；批次效期三色；发货 → WMS 出库完成自动回写发货状态 → 应收按发货单号生成 → 凭证。
- 讲：物流每动一步，账就自动跟一步——账实一致不是月底对出来的，是每一步实时成立的。

## 第 8 段 · 收尾（2 分钟）

- 页面：回到履约时间线。
- 动作：刷新，展示开场时空着的节点已逐一点亮，每个节点可下钻到刚才操作过的真实单据。
- 讲：回扣三个记忆点。结束语：今天演示的每一步都有独立可复验的证据（主链连续 5 次、异常支线各 3 次全绿）。
