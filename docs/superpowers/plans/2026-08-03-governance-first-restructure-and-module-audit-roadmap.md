## 0. 背景与 owner 决策

第一阶段领导演示（2026-08-01）为两周赶工产物，期间引入的问题数量未知。owner 明确：

1. **演示语境收口**：纯演示服务类 issue 直接关闭；借演示走查暴露的真实产品缺陷分流保留。
2. **从基本盘入手**：先改进整个项目的治理结构，再逐模块找问题、改进、优化，设立路线图。
3. **业务语义已部分失控**：「非常多业务逻辑我已经无法掌握甚至已经偏离」——重建 owner 对业务事实的掌握是第一目标，不是附带产物。
4. 模块轮审起点：**MasterData/IAM 语义地基**；在途项目（PDA 现场作业、CAD 预览、FileStorage 及各停摆前端项目）**全部冻结让位**。

## 4. L3 模块轮审与业务语义纠偏（新项目）

### 4.1 每模块三件产出（固定模板）

1. **业务语义偏离台账**：代码实况 vs `docs/architecture/*-product-design.md` vs owner 业务认知，逐条核对；分「文档错 / 代码错 / 两者都偏离业务本意」三类。**语义核对由 owner 拍板**。

3. **模块小路线图**：修复顺序、依赖、验收方式（含真机走查项）；产品设计文档同步刷新。

审计约束：以 PR 树/真机为准，不以门禁绿为据；开场先分诊本域残留票；横切问题归 R8 或治理项目，不顺手扩修；新 issue 先建 GitHub 自动同步。
