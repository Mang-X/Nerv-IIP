# ADR 0032：解冻 L3 自动局部重排，冻结集先行与候选发布边界

- 状态：已接受
- 日期：2026-09-30
- 部分修订：[ADR 0022](0022-scheduling-rescheduling-evolution-freeze.md) §8、§9、§11 及其后果第 4 条；其余条款仍有效。

## 背景

ADR 0022 确定了 L1 失效、L2 人工工作台、L3 影响分析与局部候选生成的分层，但将规则源/引擎抽象列为 L3 的开工前置，稳定窗口与停机恢复输入也未定型。#3614 记录的 owner 裁决是：L3 是成熟排产产品必需能力，解冻实施；不以 A 组工程抽象或另开工程内务票阻塞业务交付。

本记录裁决 L3 的输入、四策略、冻结与候选确认边界，供实现票独立评审。解冻表示允许按依赖推进，不表示已有 L3 实现，也不授权无人值守发布或生产批次拆分。

## 决策

### 1. 交付依赖与保持的边界

规范性顺序改为 **冻结集契约 → L3 影响分析与候选生成 → 拆批**。设备恢复时间等来源投影可与冻结集并行准备；候选比较与流程接入建立在 L3 输出之上。偏差投影接入、失效提醒与人工处置入口仍可先行，遵守 ADR 0022 §10，不在流程层复制影响分析。

本条取代 ADR 0022 §11 的“A 组抽象先于 L3”要求，以及后果第 4 条将抽象/追溯字段另拆代码票作为关闭条件的要求。ADR 0022 §1–§5 的概念分离、纯引擎输入输出、追溯与 MES 边界继续有效；实现 L3 时只落实业务所需边界，不以增加可替换抽象为独立前置项目。

ADR 0014 §12、§13、§14、§17、§18 继续约束本记录：无 IO/系统时间/随机数/本地时区；同一规范化输入得到相同结果与指纹；排序不另造紧急度键；冻结 assignment 不因冲突被挪动；preview 不写 MES，released 才能通过 MES 命令落地。

### 2. 标准化偏差与 ETR/MTTR 输入

服务层组装同组织、环境的 `SchedulingProblem`、基线 `SchedulePlan`、偏差事实集、执行状态、冻结策略与显式计算时刻 `AsOfUtc`。偏差携带稳定来源引用、发生时间、受影响工单/工序/资源标识及该类偏差所需事实；来源投影仍归各来源域，Scheduling 不跨 schema 读取。

停机输入必须区分**实际停机、预计恢复、实际恢复**：

1. 停机开始使用来源 `FromUtc`；维修人员填写或更新的 ETR 使用 `ExpectedRestoreAtUtc`。实际恢复事实一旦到达，按实际恢复结束阻塞，不把预测写成实际事实。
2. 无显式 ETR 时，服务层使用该设备已结束停机记录的 MTTR（停机持续时间算术平均值）；无历史时使用受治理配置的默认时长。统计范围、样本窗口与配置值由来源实现票定义，计算核心只接收选定时长和依据。
3. 估计恢复时刻为 `FromUtc + MTTR`，并携带“显式 ETR / 设备 MTTR / 配置默认”来源及来源版本。估计过期而设备仍停机时，不视为已恢复，不允许在已知停机时段内安排生产；该候选保留恢复预测已过期的说明，等待更新事实后重预览。
4. 超过配置阈值仍未恢复时，来源/流程层升级通知计划员；统计、通知与读取当前时间均在计算核心外。核心不轮询设备、不发送通知、不自行延期 ETR。

ETR/MTTR 使等待与转移的代价可比较；它们是有来源的预测输入，不是“到时必恢复”的承诺。输入指纹覆盖恢复依据、偏差、冻结策略与 `AsOfUtc`；服务层快照相同，重复计算不能因机器时钟变化得到另一候选。

### 3. 冻结集与影响分析

本节取代 ADR 0022 §8 将稳定窗口精确定义留给实现票的部分。

冻结集为基线中**已完成 ∪ 已开工 ∪ 人工锁定 ∪ 稳定窗口内**的 assignment。已开工包含暂停、停机或质量阻断中的已开工工序；阻断不能使其重新成为可移动工序。未开始的过期计划不因时间已过去就被推定为已开工。

稳定窗口使用显式 `AsOfUtc` 和非负时长 N，区间为 `[AsOfUtc, AsOfUtc + N)`，按基线 assignment 的 `StartUtc` 判定；N 可按工作中心覆盖，未覆盖使用统一默认。N = 0 表示不增加未来稳定窗口冻结，不解除执行状态或人工锁。边界与所用策略进入输入快照，前端不自行计算另一套冻结集。

冻结 assignment 的资源、开始、结束原样保留，并参与产能、日历、停机等校验。与新事实矛盾时输出冲突，不通过移动冻结项制造可行候选。冻结是保持位置的约束，不是发布授权。

影响分析沿工序依赖与资源占用传播，输出受影响集、传播路径/原因、冻结集与需重算集；需重算集只含受影响且可移动工序。只有传播证明全局受影响时才允许全量重算，并记录全局结论。未受影响的 assignment 保持基线位置；受影响但被冻结的工序保留冲突解释，不能从结果中消失。

### 4. 四种候选策略

四策略共享同一影响分析、冻结集、有限产能/日历/前后置/物料/质量约束与确定性排序。策略不保证一定产出可发布方案；不可行时给出冲突或未排原因，不能悄悄改用全厂重算。

| 策略 | 适用条件与行为 | 必须能验收的结果 |
| --- | --- | --- |
| 右移（right-shift） | 停机或前序延迟后仍可等待原资源；保持原资源和受影响队列的相对顺序，把可移动工序后推至满足恢复、日历及前序约束的最早位置 | 原资源不变；后继传播可解释；未受影响和冻结项位置不变 |
| 拆插（局部序列插入） | 急单或新增需求需要插入现有队列；拆开受影响的未开始工序序列，插入完整新工序，再按既有排序重排该局部链路 | 列出被推迟工序及延迟量；不拆订单数量、不拆工序执行片段、不打断已开工工序 |
| 转移（resource transfer） | 原设备等待代价较高且存在合格备选设备；候选设备取工序 `EligibleResourceIds` 与可用设备交集，IIoT 替代设备事实不能扩大工艺资格，换型占用和代价纳入比较 | 给出原/新资源、换型代价与替代设备来源；不把“不知道设备状态”伪装成已恢复 |
| match-up（回接基线） | 扰动消退后，局部链路能够在基线某个后续位置重新接上；回接点及之后仍须满足前序、资源和日历约束 | 标出回接点；回接点之后可保持的 assignment 与基线一致；找不到可行回接点时说明不可行 |

“拆插”在本记录中指队列插入，不等于 ADR 0022 §12 的生产订单拆批、转移批量或多设备并行。那些能力仍后置并要求契约演进评审。四策略可以分期交付；比较的是具备适用条件的实际候选，不生成占位候选。任何策略实现 PR 都须引用本记录。

### 5. 候选、六项 KPI 与原因

本节补充 ADR 0022 §9：候选统一为 `Preview`。计划员在同一工作台比较并选定后，保存为 `WorkingScheduleDraft` 的 generated 修订，再走既有确认、release/supersede 链；自动生成候选不等于自动选定，不增加第二个发布入口。新偏差或基线变化后，候选须用新输入重预览，不能把旧候选当作新事实的确认。

每个候选给出以下六项与同一基线的对比；计算口径、资源范围、排程窗口和冻结策略须一致，准交率同时展示各自的分母：

| KPI | 口径 |
| --- | --- |
| 准交率变化 | 沿用现有 `OnTimeRate` 的**可优化已排工序**口径，候选减基线；不能将其标成订单准交率。锁定工序不进入该分母，未排数量由独立 KPI 显示 |
| 延期订单数 | 按 `(OrderId, OperationId)` 对照输入 `DueUtc`；至少一道已排工序 `EndUtc > DueUtc` 的订单去重计数（包括冻结工序），并展示基线、候选及差值。现有 `LateOperationCount` 是工序数，不可冒充订单数 |
| 移动工序数 | 基线与候选中同一工序的资源、开始或结束发生变化计一次；新插入和移至未排的工序另行说明。执行中工序冻结，不计为可移动项 |
| 资源利用率变化 | 沿用 `AverageResourceUtilization`：资源窗口总占用分钟 / 总可用分钟，候选减基线；使用相同资源与窗口，不取各资源百分比的简单平均 |
| 未排工序数 | 使用候选 `UnscheduledOperations` 数量，展示基线与差值，不将未排当作准时完成 |
| 锁定保持情况 | 逐个基线锁定工序核对资源、起止时间是否保持，给出保持/总数及未保持明细；仅展示候选锁定数量不能证明保持 |

这对 ADR 0022 §9“全部指标沿用基准脚本既有定义”作精确修订：已有工序 KPI 继续复用，延期**订单**与逐项锁定保持是必须补齐的语义，不把已有字段改名当作实现。

每个移动工序必须给出原因码、触发偏差来源、传播路径、原/新资源与时间；转移给换型与设备来源，match-up 给回接点。未排、冻结冲突与新插入也须可解释。前端展示业务说明和页内关联明细，不让用户通过页面互跳拼出因果，不在前端生成权威原因或 KPI。

### 6. 验收不变量

实现须证明以下业务不变量：

- 同一规范化输入（包含 `AsOfUtc`、偏差与恢复依据）重复计算，影响集、候选与指纹相同；重排内核无 IO。
- 单设备停机只传播到有依赖/资源影响的链路；独立订单保持位置。冻结项即使冲突也原样保留且冲突可见。
- 有 ETR、无 ETR 使用设备 MTTR、无历史使用配置默认、预测过期仍停机、实际恢复五种输入能区分；预测不自动解除实际停机。
- 四策略按适用条件验证上表结果；插单不拆生产批次，转移不越过工艺资格，match-up 不以回接为由忽略产能或前后置。
- preview 不改变 MES；选定候选后仍须草稿确认与发布权限；新版发布按既有治理取代旧版本。
- 六项 KPI 和每个移动工序的原因来自后端同一输入；未排、冻结冲突与延期不得被隐藏。
- 局部重排继续满足 ADR 0022 §14 的同档位中位耗时 ≤ 对等全量重算 50% 门槛；无基准证据不宣称局部重排性能达标。

## 理由与替代方案

1. **继续等待 A 组抽象后才实现 L3。** 不采用。概念边界仍必须遵守，但抽象本身不能替代影响传播、冻结和候选业务行为；将它作为前置会延迟 owner 已裁决必需的能力。
2. **维持 L1/L2 全量重预览作为长期方案。** 不采用。它不能证明只移动受影响链路，也不能提供等待、插入、转移与回接的可比较选择；已有 L2 保留为人工处置能力。
3. **候选引擎自行读设备状态、取当前时间并自动发布。** 不采用。输入无法回放且计算/事实/授权边界混合，违反 ADR 0014 §12、§14。服务层组装事实，核心计算，计划员确认发布。
4. **本轮同时引入拆批、多设备并行或全局优化器。** 不采用。它们改变数量与执行追溯或求解边界，无法与“不改冻结项、只动受影响链路”的首轮验收混审；继续遵守 ADR 0022 §3、§12。

## 实施说明与后果

- 本记录是 ADR 0022 的部分修订：§8 稳定窗口在本记录 §3 定义；§9 KPI 在本记录 §5 澄清；§11 交付前置与后果第 4 条在本记录 §1 取代。旧条款作为历史判断保留，0022 头部与实施说明反向链接本记录。
- 当前结构和事实所有权仍从 [`../architecture/overview/context-map.md`](../architecture/overview/context-map.md) 与 [`../architecture/business/domain-architecture.md`](../architecture/business/domain-architecture.md) 读取。实现状态、子票拆解与验收证据留在 GitHub/Linear；不得因本记录已接受而把产品页面标成 L3 已可用。
- 现有工作台产品语义见 [`../product/scheduling/design.md`](../product/scheduling/design.md)。实现 PR 随行为变化更新该 Product；用户教程与产品站按 ADR 0021 同步评估。
- 恢复预测与基线输入需要可追溯，冻结冲突会导致部分候选不可发布；这是事实与冻结约束的结果，不能通过忽略冲突或自动解锁消除。
- 复评触发条件：需要打断已开工工序、把拆插扩为数量拆分、引入求解器/全局优化器、无人值守发布、改变 KPI 分母或取消冻结保持时，必须新建或修订 ADR。

## 范围之外

本记录不实现算法、公开字段、DB migration、来源统计或工作台 UI；不创建工程内务前置票；不裁决生产批次拆分的数量规则、工序重叠或转移批量契约。这些实现须按各票当前事实另过 Scope Gate，L 母票不得直接承载代码。
