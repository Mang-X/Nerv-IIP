# 工厂设定与人工走查最小数据

本文是工厂设定与人工走查数据的当前权威来源。历史形成过程保留在
[`2026-07-26-factory-world-bible.md`](../../superpowers/plans/2026-07-26-factory-world-bible.md)，
该文件是不可改写的 Superpowers 历史快照；后续设定与走查数据调整只修改本文及其代码投影。

## 1. 目标与边界

人工走查必须能在不依赖大规模背景历史的干净本地环境中完成 ERP 采购链和销售链。最小数据只提供：

- 可选择的结构性主数据；
- 一套可人工复算的采购价与销售价；
- 一个成品的 BOM、工艺路线、生产版本和工时定额；
- 可继续转业务单据的询价、供应商报价和销售报价起点。

最小数据不创建采购订单、收货、销售订单、发货、应收应付、凭证、库存余额或生产结果。
这些结果必须由走查者通过公开业务路径产生，避免页面非空被误报为真实流程通过。

## 2. 工厂基线

- 组织：`org-001`；环境：`env-dev`；厂区：`SITE-001`（一号工厂，`Asia/Shanghai`）。
- 业务背景：乘用车悬架减振器及核心零部件。
- 结构：3 个车间、14 条产线、17 个工作中心；最小投影保留该结构以承载完整八道工序，
  但不写入全量 46 台设备和 58 名员工。
- 工作制：早班 08:00–16:00、中班 16:00–24:00；标准日历编码 `STANDARD`。
- 全量设定仍采用 84 SKU、8 客户、10 供应商以及 L0/L1/L2/L3 分层；它只用于需要整厂背景的
  专项场景，不再是日常人工走查的前置。

## 6. 启用与隔离

本地 AppHost 默认向 MasterData、ProductEngineering 和 ERP 注入
`Walkthrough:Seed:Enabled=true`。单次会话可用 `NERV_IIP_WALKTHROUGH_SEED=false` 关闭。
三个服务只允许在 `Development` 环境执行；重复执行幂等，同号保留事实不兼容时失败且不覆盖。

最小投影与 `LeaderDemo:World:*`、`LeaderDemo:History:*` 独立。验收时必须关闭旧全量世界和历史，
并用 `*-WALK-*` 业务编号与本节明确的主数据编码取证，避免旧数据造成非空假阳性。

## 7. 走查与前置核对

1. 在隔离真栈中关闭全量世界、背景历史和规模块，保留最小投影。
2. 采购链从 `RFQ-WALK-001` 的供应商报价创建采购订单，经审批下达、收货与入库；采购订单、
   收货页面须能按本次业务编号找到记录。
3. 销售链从 `QUO-WALK-001` 创建销售订单，经需求、生产/备货、发货与应收；销售报价、订单、
   发货页面须能按本次业务编号找到记录。
4. 页面证明必须同时包含真实 GET 200、稳定业务编号行和空态文案未出现；单元测试或 API 成功
   不能代替真浏览器页面证据。

以下能力属于独立任务，本票只登记其走查前置，不复制其实现：

| 前置 | 本票核对口径 |
| --- | --- |
| [#1793](https://github.com/Mang-X/Nerv-IIP/issues/1793) 审批模板 | 采购下达至少需要 `purchase-order-release` 模板；缺失时采购链必须失败关闭，不允许在走查脚本临时造模板。 |
| [#1792](https://github.com/Mang-X/Nerv-IIP/issues/1792) 开箱岗位角色 | 管理员可验证结构链，但不能证明采购、销售、财务岗位开箱权限；岗位验收仍由该票拥有。 |
| [#1759](https://github.com/Mang-X/Nerv-IIP/issues/1759) Forecast 管理入口 | 销售订单可形成需求，但不能据此声称 Forecast 用户入口已完成；该页面缺口仍由该票拥有。 |

## 8. 变更与签字

最小目录、价格或工时变更必须同时更新本文、对应服务的 `WalkthroughSeedSpec` 与行为测试。
本文的 owner 签字以关联 PR 的批准审核为准；PR 未获 owner 批准时，只能称为待签字候选，
不得据此放行删除全量世界观种子的后续层。
