# 前端导航产品信息架构

本文定义 Nerv-IIP 跨端导航的**当前产品语义**：不同角色从哪里进入、如何在能力域之间切换、如何找到业务对象，以及 PC 与 PDA 各自采用什么任务范式。它不记录页面是否已交付、Gateway 覆盖率、固定端口、Issue/Phase 或 CI 状态。

实现清单与当前代码入口见 [`../reference/frontend/navigation-map.md`](../reference/frontend/navigation-map.md)；当前工程约束见 [`../governance/frontend/navigation.md`](../governance/frontend/navigation.md)；壳层与应用边界见 [`../architecture/frontend/navigation.md`](../architecture/frontend/navigation.md)。

## 1. 三类入口

### Platform Console

面向平台管理员和运维角色，承载 IAM、应用/实例、运维、通知、文件与平台监控等通用控制面。业务域 CRUD 与业务工作流不进入 Platform Console。

### Business Console

面向计划、生产、仓储、质量、设备、经营等业务角色，是桌面端业务操作入口。导航按“能力域 → 模块/任务 → 页面”组织，但用户看到的集合必须依据角色和权限裁剪，而不是把完整能力目录作为默认侧栏。

### Business PDA

面向一线执行角色，采用任务优先而不是 PC 菜单树优先的范式。首页优先呈现我的任务、快捷入口和扫码；扫码或业务对象识别后直接进入报工、收货、上架、拣货、盘点、巡检、报修等对应工作流。

## 2. 桌面端信息架构

1. 长期桌面导航采用顶部能力域 + 左侧域内导航的 T 型结构。
2. 逻辑层级最多三级：**域 → 模块/任务组 → 页面**。更深的对象关系进入页面内树、Tab、Drawer、Sheet 或详情，而不是继续扩菜单树。
3. “创建、编辑、审批、确认、关闭、打印、报工、入库、排程运行”等动作属于页面操作，不是菜单项。
4. 物料、工单、订单、设备、批次等对象详情不是常驻菜单项，应从列表、搜索或上下文关联进入。
5. 页面内 Tabs 表达同一对象的不同视图，不进入全局导航树。
6. 能力目录描述产品边界，不等于任何具体角色的默认可见菜单。
7. 顶部空间不足时，低频能力进入“更多”或应用切换器，不通过换行、压缩内容区或在页面局部增加第二套导航解决。

## 3. 角色与发现能力

- 一线和专岗角色默认只看到与当前任务直接相关的工作台和少量入口。
- 厂长、生产负责人、超级管理员等跨域角色需要“近期使用”“星标收藏”和全局发现能力，不能依赖展开完整长菜单完成跨域工作。
- 全局命令/对象搜索应支持按菜单名以及物料、工单、采购单、销售单、设备、批次等业务对象进入相应页面或详情。
- 搜索负责“找到入口/对象”，不绕过对象本身的权限和范围约束。

角色画像用于确定**默认信息密度和入口优先级**，不是 IAM permission catalog 的副本：

| 角色画像 | 默认优先能力 | 不应默认暴露 | 产品原则 |
| --- | --- | --- | --- |
| 生产计划员 | 数字化工作台、需求与计划、制造执行中的计划/工单/派工、库存与产品工程只读上下文 | 财务、设备运维、平台系统管理 | 以需求/MRP/MPS → 工单 → 齐套与执行为主链路；采购与库存通过上下文进入 |
| 仓库管理员 | 数字化工作台、仓储作业、库存、条码、来料质量入口 | 产品工程、高级排程、财务、审批模板配置 | 收货、上架、拣货、复核、发货、盘点是主任务；库存事实应在作业页就地可见 |
| 质量工程师 | 数字化工作台、质量管理、MES 质量/不良、库存冻结与批次、供应商/物料只读 | 销售、财务、排程设置 | 检验、NCR、冻结和返工通过对象上下文连成闭环 |
| 设备工程师 | 数字化工作台、设备监控、设备运维、MES 设备/停机、备件库存只读 | 销售/财务、产品工程变更、审批模板配置 | 从设备异常直接进入监控、停机、报修和维修，而不是按服务边界跳转 |
| 一线操作员 / PDA | 我的任务、扫码直达、快捷应用墙 | PC 能力目录与完整菜单树 | 报工、收货、拣货、盘点、巡检、报修等从任务或扫码进入 |

## 4. 跨域上下文穿透

后端 bounded context 不是前端用户的操作边界。一个任务可以组合多个域的事实，但应保持事实来源清晰：

- WMS 作业需要就地看到物料、库位、批次、可用量、冻结和预留等库存事实；发现缺料时，应能继续查看替代批次、冻结/预留原因以及相关入库或调拨入口。Inventory 同时保留余额、台账、批次与分析等事实视角。
- 生产驾驶舱、工单或设备异常应能带当前设备进入设备监控、OEE、停机记录，或进入报修/维修上下文；不要求用户返回主菜单重新查设备。
- 质量检验、NCR、库存冻结和返工之间应携带物料、批次、工单和检验记录上下文。
- ERP 采购收货、WMS 入库、Quality 来料检验与 Inventory 入账应通过来源单据和行号互相穿透，不要求操作者手填跨域 ID。
- MES 报工、完工入库、WMS 入库和成本相关查询应能从工单或报工记录继续下钻，不以服务名作为导航断点。
- 跨域页面以用户任务为中心聚合信息，不为“后端有一个服务”机械新增导航入口。

## 5. 业务可见命名

后端 bounded-context / 服务名可以保留在代码和架构边界中，但面向业务角色的导航应使用业务语言：

| 架构/服务语义 | 推荐业务标签 | 使用原则 |
| --- | --- | --- |
| ProductEngineering | 产品工程（PLM）/工艺工程 | 仅处理 MBOM、路线、生产版本时可使用“工艺工程” |
| IndustrialTelemetry | 设备监控（IoT） | “工业遥测”保留给架构与技术上下文 |
| Maintenance | 设备运维（CMMS） | CMMS 可作专业括注，不要求一线理解服务名 |
| BusinessApproval | 审批中心 | 待办优先进入工作台；配置与记录再进入审批中心 |
| Inventory | 库存管理 / 库存台账 | 在 WMS 作业中作为嵌入事实；独立入口承载余额、批次、台账与分析 |
| WMS | 仓储作业（WMS） | 面向仓库角色优先以收货、上架、拣货、复核、发货、盘点等任务命名 |

## 6. 工作台与发现入口

数字化工作台是跨域行动入口，不是完整页面目录：

1. 快捷入口按业务域或当前角色的高频任务组织，并落到该角色真正有权限访问的页面。
2. 待办、消息、预警与业务指标必须来自当前公开事实；来源不可用、无权限或不支持时应明确降级，不用 `0` 冒充“正常且为零”。
3. 近期、星标和全局搜索都属于导航发现能力，结果必须按当前权限与范围重新过滤。
4. 工作台负责帮助用户进入任务，不替代域内页面的 Drawer、Sheet、关联侧栏和对象详情。

## 7. 导航升级的产品判据

一个能力只有在能够形成真实、可操作、可授权的用户入口时才进入可见导航。后端存在、接口存在或设计文档存在都不等于菜单已交付。具体 route、权限和 facade 是否存在，以当前生产者为准，见 [`../reference/frontend/navigation-map.md`](../reference/frontend/navigation-map.md)。
