# 文档与协作语言治理

## 目的与权威来源

本文件规定 Nerv-IIP 人工文档和团队协作文本的中文化边界、分类和完成条件。`docs/AGENTS.md` 是触发入口，本文件是分类与完成条件的权威来源。发生冲突时，不得以翻译为由改变技术契约、命令语义或机器输入。

候选清单必须在每次治理波次和最终验收时从 Git 重新生成；下列命令是后续任务使用的权威文件清单，而不是可能过期的静态附件：

```bash
git ls-files | awk 'BEGIN{IGNORECASE=1} /(^|\/)(README|CHANGELOG|CONTRIBUTING|SECURITY|NOTICE|AGENTS|CLAUDE|GEMINI)(\.[^\/]*)?$|\.(md|mdx|markdown|txt|rst|adoc)$/{print}' | sort
```

2026-08-09 在本工作树执行时得到 573 项候选；该数字仅是本次盘点结果，最终验收必须重新执行命令。清单应覆盖根目录、`docs/`、`frontend/`、后端说明、`.claude/`、`skills/` 与 `infra/`，并将所有 `AGENTS.md`、`CLAUDE.md` 和其他人工指令文件纳入检查。

## 治理范围

下列受版本控制且由人维护的内容必须默认使用简体中文：

- 根目录和子目录中的 `README.md`、`AGENTS.md`、`CLAUDE.md`、设计说明、产品说明及其他说明文档；
- `docs/architecture/`、`docs/adr/`、`docs/demo/` 的架构、决策和演示文档；
- `docs/superpowers/plans/` 与 `docs/superpowers/specs/` 的历史计划和设计规格；
- `frontend/DESIGN/`、设计系统组件文档和产品文档；
- 人工维护的 Copilot 指令、Skill 文档、脚本使用说明及维护说明。

此规则同时覆盖 Linear：项目名称与说明、Issue 标题与正文、评论、审核意见、状态说明、验收记录、复盘结论和其他面向团队的协作文本默认使用中文。

## 保留规则

以下内容允许保留原文，且不得为提高中文比例而修改：

- 代码、命令、路径、文件名、URL、版本号、正则表达式、代码围栏及链接目标；
- API、类型、方法、变量、配置键、协议字段、数据库标识符和生成器标识；
- 产品名、库名、标准名、缩写，以及没有稳定中文译名的专业术语；
- 为可搜索性保留的英文术语；其所在叙述必须有中文解释；
- 外部英文原文的短引文；必须补充中文上下文或中文结论。

翻译必须保持需求强度、状态、数字、日期、边界条件、命令语义、表格结构、Markdown 围栏、链接及锚点不变。`MUST`、`SHOULD` 等规范词可以译为“必须”“应当”，不得弱化为可选建议。

## 机器输入排除表

下表仅排除可精确识别的机器输入或生成产物；不得以宽泛目录排除其中的人工文档。

| 路径模式 | 分类 | 不可改写原因 |
|---|---|---|
| `scripts/tests/fixtures/test-evidence/**` | 测试夹具、TRX、JSON、日志 | 测试以字节、字段和值验证解析、脱敏和失败分支；改写会改变输入语义。 |
| `scripts/tests/fixtures/backend-test-determinism/**` | 测试夹具 | 源码片段和 baseline 是确定性检查器的受测输入，改写会改变扫描结果。 |
| `scripts/tests/fixtures/fullstack/**`、`scripts/tests/fixtures/script-governance/**` | 测试夹具 | 模拟外部命令与治理失败条件，内容由断言按原样读取。 |
| `frontend/DESIGN/roadmaps/assets/**/l2-run-fingerprint.txt` | 指纹 | 用于识别特定运行，必须保持字节稳定。 |
| `scripts/tests/fixtures/test-evidence/*.log.txt` | 日志样本 | 用于日志解析和脱敏测试，文本是程序输入。 |
| `docs/superpowers/fixtures/**/*.json` | 协议/测试样本 | 结构和值供脚本或验证使用，不能作为自然语言翻译。 |
| `frontend/packages/api-client/src/generated/**` | 生成文件 | 由 OpenAPI/代码生成器生成，禁止手工编辑。 |

不在表中的候选文件必须先按“人工叙述”处理；若发现新的机器输入，应先证明其消费方式，再以精确路径模式、分类和原因补充本表，不能直接排除整个父目录。

## 扫描与分类

每轮扫描的结果必须逐项归入以下三类：

1. **必须翻译**：代码围栏外的英文标题、连续英文叙述、表格中的英文业务说明，以及 AGENTS、CLAUDE、Copilot、Skill 指令中的英文自然语言；应翻译为简体中文。
2. **合法保留**：符合“保留规则”的代码、标识符、专业术语、短引文或带中文上下文的可搜索英文；记录其上下文，不以英文字符数量判失败。
3. **机器输入排除**：精确命中本表的文件；保留其路径、分类和原因。

禁止建立按英文字符比例、中文字符比例或单纯正则命中即失败的门禁：这些规则会误判代码、标识符、专业术语和协议样本。扫描应结合代码围栏、文件分类和人工语义裁决，重点检查标题、连续叙述、表格说明、指令文本、未登记排除项以及围栏/链接/锚点/表格/规范语义是否受损。

## 实施与审核角色隔离

控制代理只负责候选清单、分区、任务台账、冲突协调和最终验收，不与实施代理混合修改。实施任务按互不重叠的目录切分；同一轮代理不得编辑同一文件。每个实施任务结束后，由独立审核代理检查翻译完整性、技术语义和格式；实施者不得审核自己的结果。审核发现的问题由实施代理修复后，再由独立审核代理复核。

## 完成条件

治理循环只能在下列条件均满足时结束：

1. 从 Git 重新生成候选清单并产出分类统计；
2. “必须翻译”清单归零，英文标题和英文叙述扫描不存在未裁定命中；
3. 所有根级与子目录 `AGENTS.md` 都未削弱全局中文规则；
4. 合法保留项经过人工抽查，机器输入排除项均有精确登记原因；
5. Markdown 围栏、内部链接、相对路径、锚点和表格结构保持有效；
6. `git diff --check` 通过；若变更了治理脚本，`scripts/check-script-governance.ps1` 也通过；
7. 独立全分支审核不存在未处理的严重或重要问题。

本治理不修改业务代码、公开契约、数据库、生成客户端或机器证据，也不执行推送、创建 PR 或修改 Linear 数据。
