本矩阵是当前有代码支撑的公开集成事件和业务服务本地集成事件决策记录。它防止旧的
`#419`/`#485`“已发布但未消费”列表在未核查源码时被当作当前事实。

## 范围与证据

源码事实收集自：

- `backend/common/Contracts/**` 下的公开契约事件。
- `backend/services/Business/**/Application/IntegrationEvents` 下的业务服务本地集成事件。
- 以 `IntegrationEventConsumer` 或 `CapSubscribe` 声明的活动消费方，位于服务 `Application/IntegrationEventHandlers` 下。
- `#485` 元跟踪项下的既有后续 Issue。

ADR 0011 仍是所有公开或跨服务边界事件的信封、版本和幂等性基线。未实现
`IIntegrationEventEnvelope` 的服务本地事件记录，必须保持本地并在此登记，或者在另一服务消费前通过专门的
契约与可靠性 Issue 升级。

分类值：

- `consumed-internally`：仓库内服务当前有真实处理器。
- `needs-business-consumer`：真实业务流程尚未闭合；该行关联既有 Issue、负责后续工作的 `#485` 子 Issue，或在尚无子 Issue 时明确标为等待 `#485` 分诊的缺口。
- `audit-or-external-only`：当前不要求平台内状态变更；事件用于审计、可观测性、已在别处覆盖的通知或外部扩展消费方。
- `producer-only-until-feature`：生产方契约有用，但仓库当前使用查询与解析 API 或未来功能边界，而非消费方。
- `deprecated/covered-by-other-contract`：当前代码以更新或更窄的契约完成作业交接。

## 后续 Issue 映射

`#485` 是仍然开放的元跟踪项，当前子 Issue 覆盖：

- `#507`：新增更多 ERP 消费方前的 ERP 消费可靠性基线。
- `#508`：DemandPlanning 已接受采购建议到 ERP `PurchaseRequisition`。
- `#509`：由采购收货事实驱动的采购到付款 AP 自动化。
- `#510`：由 WMS 出库完成事实驱动的订单到收款 AR 自动化。
- `#512`：saga/process-manager（过程管理器）与 choreography/compensation（编舞和补偿）ADR。
- `#690`：IndustrialTelemetry `DeviceStateChanged` 下游消费到运行时可用性和面向 Scheduling 的计划失效。

本矩阵不会关闭 `#485`。`#551` 收口分支新增 Scheduling 冲突通知消费方，并为其余审核事件记录既有消费方或预留边界。2026-07-03 的现场能力批次（#683-#689）增加规划消费方与 connector/historian（连接器和历史数据）跟踪项，但在代码增加相应处理器或 `CapSubscribe` 订阅前，本矩阵不得将这些消费方标记为已交付。

## 就绪度说明

- 必需的契约门禁保持为
  `dotnet test backend/tests/Nerv.IIP.Contracts.IntegrationEvents.Tests/Nerv.IIP.Contracts.IntegrationEvents.Tests.csproj --no-restore`.
- 该门禁发现被引用的公开非泛型 `*IntegrationEvent` 契约，并验证 ADR 0011 信封结构。它不证明每一种
  事件类型都有业务消费方。
- 必须根据本矩阵和活动处理器注解审核消费就绪度。无消费方的事件仅在分类为
  `needs-business-consumer` 时才是缺陷。
- 本矩阵的 `needs-business-consumer` 行有意映射到既有 Issue（`#508`、`#509`、`#510`）、其前置子 Issue
  （`#507`），或尚无具体子 Issue 时明确标示的 `#485` 分诊缺口。本文档不创建额外 GitHub Issue。
