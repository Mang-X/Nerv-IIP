# 质检员：第一周路径

质检员把检验与不合格处置走成闭环。第一周先走通下面 7 条路径，每条路径都以一个业务结果收尾。
状态口径见[按角色入门](/roles/)。

## 第一周路径

| #   | 路径（页面操作串）                                                          | 业务结果                               | 状态                                                                                                                                                                |
| --- | --------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 在 `/quality/inspections` 配置首件检验方案，执行检验后独立查询并打印记录    | 首件检验项与执行记录可追溯             | ✅ 可用；首件方案按物料与工序工作中心限定适用范围，首件记录与普通检验记录分开查询                                                                                   |
| 2   | 在 `/quality/inspection-tasks` 按来源和时限处理待检任务，进入检验后提交结果 | 待检任务不遗漏，并在提交检验记录后闭合 | ✅ 可用；支持从 WMS 收货单按真实来源单号定位对应待检任务                                                                                                            |
| 3   | 检验不合格时在 `/quality/ncrs` 开 NCR                                       | 不合格品进入受控处置                   | ✅ 可用                                                                                                                                                             |

| 6   | 在 `/quality/reason-codes` 维护原因码                                       | 检验与处置有统一原因口径               | ✅ 可用                                                                                                                                                             |

## 从工序检验接续现场不良

✅ 可用：有效工单、工序来源的检验提交后，可在已有授权内接续同来源不良登记并返回来源工序。操作步骤见[从工序检验接续现场不良](/how-to/continue-operation-inspection)。

## 从现场不良接续处置

- ✅ 可用：`/mes/quality` 不良记录 → 真实 NCR 编号 → `/quality/ncrs` 对应处置详情；未生成 NCR 与关联读取失败分别提示。
- 登记现场不良后，NCR 的列表摘要与处置详情保留来源工单的真实 SKU。打开处置前核对物料和来源不良单号；返回工单入口沿用带入的工单上下文。从带有工单、工序来源的入口进入 NCR 后，可用「返回工单」回到同一工单并定位来源工序；仅有工单来源时只返回工单。该入口需具备工单读取权限，无来源时仍按正常 NCR 路径处理。
- 旧不良消息缺少产品身份时，列表与详情显示「未解析物料」。这表示产品身份尚未解析，不能据此当作真实物料处置；系统不自动替换为目录中的任意 SKU，也不自动补写历史 NCR。

## 提交超时与重试

检验提交为同一次用户意图生成稳定意图键。网络超时或请求失败后再次提交相同内容会复用该键，服务端回放首次创建的权威检验记录；只有收到已确认的记录 ID 后，下一次新提交才换键。同一键不得修改检验结果、数值、原因或附件，系统会拒绝不同载荷，避免一次操作生成两份检验事实。

## 首件检验

首件检验方案使用独立档类型，并同时限定物料与工序工作中心。方案至少包含一个检验项，创建后需启用才可用于执行。首件记录以独立来源类型保存，可按物料和判定结果筛选；打开记录详情后可使用浏览器打印，打印内容包括来源单据、物料、批次或序列号、检验数量、结论、处置说明和各项实测值。

本页只交付 Quality 侧首件方案和记录事实。工单或换型后的首件触发由 [#2779](https://github.com/Mang-X/Nerv-IIP/issues/2779) 落地：工序开工后的第一件报工自动开出首件检验任务。“首件未判合格不得继续批量报工”的 MES 门禁由 [#2780](https://github.com/Mang-X/Nerv-IIP/issues/2780) 落地在服务端报工提交路径上，因此首件结论现在**直接决定**该工序能否继续报工——判不合格或让步放行都不解锁批量生产，须纠正后重新首检合格。

## PDA 我的待检

PDA 检验任务页只显示明确派给当前登录检验员本人的待检任务，不再把组织待检总量称为“我的任务”。
待领取任务会先按当前版本原子领取；领取成功后才进入逐特性录入。被其他人领取、已经完成或超出本人
授权范围的任务保持只读并显示阻塞原因，不能继续提交。

任务列表支持按来源类型、来源服务、来源编号或物料关键字、超期和状态做服务端筛选，筛选后的总数与分页一致。扫码内容同样作为服务端关键字条件，不会为了找命中项在 PDA 端拉取全部任务。
任务详情同时显示抽样规则、检验特性、当前归属和可执行动作。派工或转派由有管理权限的人员完成；
目标人员和班组来自系统目录，转派必须填写原因。

提交检验结果后，PDA 先按任务 ID 确认任务已经完成并关联了本次检验记录，再按检验记录 ID 读取权威结论。只有两次读取一致时才展示合格、不合格或条件放行；HTTP 200、提交前预判或当前页缓存都不单独作为完成证据。
