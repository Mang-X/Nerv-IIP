# 质检员：第一周路径

质检员把检验与不合格处置走成闭环。第一周先走通下面 7 条路径，每条路径都以一个业务结果收尾。
状态口径见[按角色入门](/roles/)。

## 第一周路径

| #   | 路径（页面操作串）                                                          | 业务结果                               | 状态                                                                                                                                                                |
| --- | --------------------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 在 `/quality/inspections` 执行检验并记录结果                                | 形成通过/不通过的检验记录              | ✅ 可用                                                                                                                                                             |
| 2   | 在 `/quality/inspection-tasks` 按来源和时限处理待检任务，进入检验后提交结果 | 待检任务不遗漏，并在提交检验记录后闭合 | ✅ 可用；支持从 WMS 收货单按真实来源单号定位对应待检任务                                                                                                            |
| 3   | 检验不合格时在 `/quality/ncrs` 开 NCR                                       | 不合格品进入受控处置                   | ✅ 可用                                                                                                                                                             |

| 5   | 对重复问题发起纠正预防与评审                                                | 不合格原因得到系统化跟踪               | 🟡 部分可用：NCR 详情的 CAPA/MRB 深化未交付（[#804](https://github.com/Mang-X/Nerv-IIP/issues/804)）                                                                |

## 提交超时与重试

检验提交为同一次用户意图生成稳定意图键。网络超时或请求失败后再次提交相同内容会复用该键，服务端回放首次创建的权威检验记录；只有收到已确认的记录 ID 后，下一次新提交才换键。同一键不得修改检验结果、数值、原因或附件，系统会拒绝不同载荷，避免一次操作生成两份检验事实。

## PDA 我的待检

PDA 检验任务页只显示当前登录检验员明确被派的 Self 待检，不再把组织待检总量称为“我的任务”。
待领取任务会先按当前版本原子领取；领取成功后才进入逐特性录入。被其他人领取、已经完成或超出本人
授权范围的任务保持只读并显示阻塞原因，不能继续提交。

任务列表支持按来源类型、来源服务、来源编号或物料关键字、超期和状态做服务端筛选，筛选后的总数与分页一致。扫码内容同样作为服务端关键字条件，不会为了找命中项在 PDA 端拉取全部任务。
任务详情同时显示抽样规则、检验特性、当前归属和可执行动作。派工或转派由有管理权限的人员完成；
目标人员和班组来自系统目录，转派必须填写原因。

提交检验结果后，PDA 先按任务 ID 确认任务已经完成并关联了本次检验记录，再按检验记录 ID 读取权威结论。只有两次读取一致时才展示合格、不合格或条件放行；HTTP 200、提交前预判或当前页缓存都不单独作为完成证据。
