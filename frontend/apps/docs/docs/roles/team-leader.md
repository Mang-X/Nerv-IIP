# 班组长：第一周路径

班组长把工单变成合格的完工产出。第一周先走通下面 7 条路径，每条路径都以一个业务结果收尾。
状态口径见[按角色入门](/roles/)。

## 停机登记与安全重试

班组长在 `/mes/downtime` 选择当前可见且同时具备工单、工序、工作中心和设备上下文的任务，再选择已配置的
停机原因和实际开始时间。系统只在当前账号拥有停机登记权限、组织与环境有效，并且实时授权范围仍覆盖该
任务时发送请求；缺少任一上下文、原因、权限或有效时间都会停止提交，不会用占位值登记。

登记受理后，页面显示服务返回的真实停机事件标识并刷新列表。若服务拒绝，页面保留服务原因供排查；
未改变表单内容时再次提交会复用同一幂等键，避免网络失败后的重复登记。恢复动作仍从同一页面的开放
停机行进入，登记入口不会改变既有恢复流程。

## 工序与报工重试

工序开始、暂停、恢复和完成在同一次失败或超时后复用意图键，服务端回放首次确认的状态和变更时间，不会重复推进生命周期；同一键改用于另一工序或动作会被拒绝。报工请求返回“已受理”后，仍须按回执中的报工 GET 路径读取权威记录，确认报工编号、数量和状态；HTTP 200 或页面乐观状态不代表报工已经确认。

## 实际工时核对

工序完成后，可在 `/mes/operation-tasks` 核对该工序累计的实际人工工时与实际机器工时；
`/mes/production-reports` 也会在每条报工旁显示其所属工序的同一累计实绩，便于从报工事实回看工序耗时。
这里不是单条报工或单个人员的工时分摊。页面显示「暂无实绩」表示工序尚未完成或冲销后已重新打开；
「0 小时」则表示服务已返回明确的零值，两者含义不同。

### 复检重放与后续轮次

复检请求以路由中的前置检验记录 ID 作为幂等身份。同一前置记录被重复提交时，服务返回已存在的直接后继，不用新载荷覆盖既有检验事实。若最新一次复检仍未通过并需要继续复检，调用方必须改用该最新未通过轮次的记录 ID；继续提交原始首检 ID 只会重放第 2 轮。
